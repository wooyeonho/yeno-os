# EXTRA-136 작업 카드 — 독자 2D 장면의 깊이 가림

**범위·출처.** 원장 EXTRA-136은 `partial/pending` 자료다. 원본 영상 전체, 사용 기기·엔진, 실제 AR 가림 동작은 확인하지 못했다. 아래 값은 원본의 재현이 아니라 이 저장소에서 만든 SVG 실험의 값이다. 장면 구현은 `scene-core.mjs`·`scene.mjs`·`index.html`, 독립 실행 파일은 `build-artifacts/handoff-r3-20260926/EXTRA-136-occlusion-offline-v3.html`이다.

**제작 입력.** 960×600 SVG에 어두운 방 배경, 중앙의 타원형 문과 불투명한 문틀·벽, 빛나는 원형 물체 하나를 쓴다. 문 개구부는 중심 `(480,286)`, 반지름 `(170,200)`의 clipPath다. 깊이 평면은 `50`; 물체 깊이 `20`은 문틀 앞에서 전체가 보이고 `70`은 문틀 뒤에서 개구부 안에 걸친 부분만 보인다. 수평 슬라이더 `0–100`은 SVG x 좌표 `180–780`에 대응한다. 물체는 뒤쪽에 있을 때 포털 clipPath 안에서만 렌더한다.

| 검증 위치 | 입력 `(수평, 깊이)` | 기대 화면 |
| --- | --- | --- |
| 앞 | `(50,20)` | 원형 물체 전체가 문틀 앞에 보인다. `frontOrb`만 표시한다. |
| 가림 | `(0,70)` | 물체가 문 개구부 왼쪽 바깥에 있어 화면에서 보이지 않는다. |
| 재등장 | `(50,70)` | 물체가 문 안쪽에서 다시 보인다. `rearOrb`만 개구부 안에 표시한다. |
| 경계 | `(78,70)` | 물체가 오른쪽 문 경계에 걸쳐 개구부 안쪽 부분만 보인다. |

**작업·검증 순서.** ① 단일 HTML을 로컬 브라우저에서 열고 `01 앞면` → `03 완전 가림` → `02 문 안쪽`을 눌러 위 세 검증 위치를 캡처한다. 이는 애니메이션을 실행했다는 뜻이 아니라 세 키프레임 비교다. ② 깊이 `70`을 유지한 채 수평 위치를 `50→78→100→78→50`으로 옮긴다. 오른쪽 문 경계에서 일부만 보이고, 바깥에서 완전히 사라졌다가, 반대로 이동하면 같은 경계에서 다시 나타나야 한다. ③ 깊이 `20`에서 수평 `0`으로 옮겨 문 바깥에서도 앞쪽 물체가 보이는 대조 조건을 확인한다.

**합격·실패.** 고정 위치 시험은 앞·가림·재등장 세 캡처의 물체 가시성과 앞/뒤 렌더 레이어가 표와 같으면 합격이다. 경계 이동 시험은 `(78,70)`에서 개구부 밖으로 물체 픽셀이 새지 않고 `(100,70)`에서 숨겨지면 합격이다. 뒤쪽 물체가 불투명한 문틀이나 벽 위로 비치거나, 앞쪽 물체가 문 밖에서 사라지거나, 상태 글자와 화면이 서로 다르면 실패다. 화면의 “3cm” 같은 물리 길이는 이 2D 시험의 판정 단위가 아니다.

**산출물·근거.** 기존 단일 HTML SHA-256은 `4672d40e6bbd75ee2857fd829cfb7fa8612858538762b581948718c9dbd25220`이다. 2026-09-27에 `scene-core.test.mjs` 3/3과 로컬 Chrome `verify-browser.mjs`를 다시 실행해 375/768/1280px 총 17장 캡처·DOM/키보드/가림 상태 검사 `ok:true`를 확인했다. 새 캡처·해시는 `build-artifacts/handoff-r3-20260926/extra136-structured-card-browser-20260927/report.json`에 있다. 768px 앞·가림·부분 경계 캡처는 사람이 열어 시각적으로 대조했다. 실제 움직임 영상, AR 카메라 추적, Android 기기·실제 공간 성능, 원본 영상의 내용은 시험하지 않았다. 이 카드는 검증된 기존 시제품을 Codex가 정리한 결과이며, 실패한 Shadow Builder가 작성하거나 독립 의미 검증을 통과한 결과가 아니다.
