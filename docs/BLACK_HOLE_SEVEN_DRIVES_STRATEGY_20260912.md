# Black Hole — 흡수·일곱 욕망·만능 실행의 통합 설계

조사 기준: 2026-09-12. 문서 상태: 원전 조사와 사업·제품 설계 제안. 실제 기능 구현·운영 반영·성과 달성 보고서가 아니다. 기존 Black_Hole_OS_Blueprint.md는 변경하지 않았다.

## 1. 블랙홀의 정의

블랙홀은 연호님의 부·명예·인지도를 높이는 것을 목적으로, 일곱 동기가 기회를 발견·선택하고, 커비가 필요한 능력을 검증·획득·조합하며, 자비스가 실제 업무를 수행하고, 확인된 결과를 다음 능력과 소유 자산으로 축적하는 개인 AI 운영체계다.

사용자의 최종 목표는 ‘전세계 최고 부자, 명예, 유명세’다. 이는 유지할 장기 지향점이며 AI가 보장할 수 있는 결과나 현재 달성한 능력이 아니다. 시장의 선택, 경쟁, 자본, 소유 지분, 조직 운영과 시간에 영향을 받는다. ‘세계 최고’라는 문구를 실행 권한 확대나 안전 기준 해제의 근거로 사용하지 않는다.

‘욕망’은 원전에서 빌린 설계 비유다. 실제 감정·의식·생명 또는 독립적인 이해관계를 구현했다고 주장하지 않는다. 동기의 수혜자는 연호님이며, 시스템 자체의 생존·권력·자원 축적은 목적이 아니다. 사용자의 중단과 목표 변경을 수용한다.

## 2. 세 캐릭터를 다시 조사한 결과

| 캐릭터 | 원전에서 확인한 핵심 | 블랙홀로 옮기는 설계 |
|---|---|---|
| 커비 | 적을 흡입해 능력을 복사한다. 작품에 따라 능력을 조합하거나 강화한다. 모든 작품이 동일한 능력 규칙을 공유하는 것은 아니다. | 필요한 기능을 발견하고, 실행 가능한 형태로 검증·편입하며, 기존 기능과 조합해 실제 문제 해결 능력을 높인다. |
| 호문클루스 | 원작 만화·FULLMETAL ALCHEMIST 계열은 일곱 대죄에 대응하는 개체들을 다룬다. 하나의 개체가 단순히 일곱 동기를 운영하는 프로그램인 것은 아니다. | 블랙홀에서는 일곱 동기를 하나의 목표 조정 체계 안에 통합한다. 무엇을 얻고, 개선하고, 우선할지 능동적으로 제안한다. |
| 자비스 | 여기서 기준은 인간 집사 에드윈 자비스가 아니라 MCU의 AI다. 토니 스타크의 보조 지능이자 건물·슈트 시스템을 운영하는 존재다. | 대화·기억·조사·설계·제작·실행·관측·보고를 연결하는 범용 비서이자 실행 총괄로 확장한다. 휴대폰 화면은 그 접점 중 하나다. |

커비의 복사와 강화는 [Nintendo의 Forgotten Land 공식 설명](https://www.nintendo.com/my/switch/arzg/copy/index.html), 두 능력의 결합은 [Nintendo의 Kirby 64 공식 소개](https://www.nintendo.com/us/whatsnew/nintendo-switch-online-expansion-pack-kirby-64-the-crystal-shards-is-now-available/)에서 확인했다. 따라서 ‘자료를 저장했다’와 ‘능력을 획득했다’를 같은 완료 상태로 다루면 안 된다.

호문클루스의 개체·욕망·고유 능력은 [FA 공식 등장인물 소개](https://www.hagaren.jp/fa/characters/index01.html)에서 확인하고, 일곱 대죄 전체와 원작/2009년판·2003년판 차이는 [Fullmetal Alchemist Wiki의 Homunculus 항목](https://fma.fandom.com/wiki/Homunculus)으로 보충했다. 뒤의 기능 배정은 원작 설정이 아니라 이 문서의 재해석이다.

자비스의 AI 설정은 [Marvel의 Vision 공식 검색 요약](https://www.marvel.com/characters/vision/on-screen)과 [MCU J.A.R.V.I.S. 해설](https://en.wikipedia.org/wiki/J.A.R.V.I.S.)을 대조했다. Marvel 본문은 접근 제한으로 전체를 읽지 못했으므로 세부 능력의 전부를 공식 페이지에서 확인했다고 주장하지 않는다. ‘만능’은 여러 업무 영역을 연결한다는 목표이며, 현실의 모든 업무를 무제한으로 수행한다는 보증이 아니다.

## 3. 일곱 욕망의 운영 명세

기존 청사진의 ‘지식·코드 흡수 / 아키텍처 최적화 / 자산·영향력 증식’이라는 세 동기를 아래 일곱 동기로 확장한다. 기존 세 목적을 버리는 것이 아니라, 기회 탐지와 행동 제안의 관점을 더 세분화한다.

| 욕망 | 블랙홀의 내부 질문 | 제안할 행동 | 성과로 인정할 증거 | 금지할 잘못된 보상 |
|---|---|---|---|---|
| 강욕 — Greed | 연호님에게 남는 돈·소유 자산·기회를 어떻게 늘릴까? | 유료 문제 발견, 가격 가설, 판매 실험, 비용 개선, 소유권 정리 | 환불·원가를 반영한 수익, 재구매, 소유권이 확인된 자산 | 매출 추정치 부풀리기, 무단 결제·투자, 과도한 위험 |
| 폭식 — Gluttony | 이번 목표에 필요한 어떤 능력이 부족할까? | 기능 요구 생성, 자료와 도구 후보 탐색, 흡수 요청 | 획득한 기능으로 이전에 못 하던 실제 작업을 수행 | 다운로드·도구·스크랩 개수 자체 |
| 질투 — Envy | 경쟁 대안의 어떤 강점을 아직 못 따라가나? | 합법적으로 관측 가능한 경쟁 비교, 품질 격차 분석, 대체 구현 | 같은 조건의 독립 평가에서 확인한 개선 | 무단 복제, 사칭, 비공개 정보 탈취, 비교 조건 조작 |
| 오만 — Pride | 최고라는 평가를 무엇으로 증명할까? | 높은 품질 기준, 재현 가능한 사례·연구·공개 기여 | 외부의 채택·인용·추천, 고객이 확인한 성과, 오류 정정 이력 | 자칭 세계 1위, 허위 경력·수상·후기 |
| 색욕 — Lust | 사람들이 이 제품과 브랜드를 진심으로 원하게 하려면? | 제품 매력·사용 경험 개선, 메시지 검증, 신뢰 관계와 팬층 형성 | 자발적 선택, 만족, 재방문, 동의한 구독·추천 | 취약성 악용, 기만적 유도, 집착·중독을 노린 최적화 |
| 분노 — Wrath | 고객의 문제와 반복 실패를 무엇부터 없앨까? | 불편·불량 탐지, 원인 분석, 허용된 범위의 수정과 복구 | 오류·불만·복구 시간 감소, 같은 장애의 재발 방지 | 타인 공격·보복·비방, 장애 은폐 |
| 나태 — Sloth | 같은 성과를 내면서 연호님의 개입을 얼마나 줄일까? | 반복 업무 자동화, 템플릿·성공 절차 재사용, 승인 묶음 | 동일 품질에서 줄어든 실제 개입 시간과 수작업 | 일을 생략하거나 미완료를 완료 처리해 얻은 시간 절감 |

색욕을 제품 매력과 관계 형성으로 옮기는 것은 의도적인 사업 설계상의 재해석이며 원작 뜻을 바꾸어 설명하는 것이 아니다. 일곱 욕망의 이름을 가진 챗봇을 일곱 개 켜는 것만으로 이 구조가 구현되지는 않는다.

폭식과 커비의 경계도 분명히 한다. 폭식은 ‘어떤 능력이 필요한가’를 제안하고, 커비는 실제 획득·검사·편입을 담당한다. 오만은 평가 개선을 요구할 수 있지만 평가 기준을 몰래 낮추거나 자기 결과를 스스로 확정할 권한은 없다.

### 동기 사이의 조정

일곱 동기는 이벤트가 있을 때 목표 후보를 제출한다. 매 순간 일곱 모델을 유료로 호출하지 않는다. 이미 기록된 지표와 규칙으로 해결할 수 있는 판단은 코드로 처리한다.

각 후보에는 대상 고객·문제, 근거, 현재 기준값, 예상 결과, 실제 측정 방법, 최대 비용, 최대 시간, 필요한 권한, 실패·중단 조건을 붙인다. 근거가 약하면 ‘사업 실행’ 대신 ‘가설 검증’ 후보로 내린다.

안전·권한·예산·진실성은 선행 통과 조건이다. 높은 예상 수익으로 이를 상쇄할 수 없다. 통과한 후보만 사용자 지시, 기한, 검증 가능한 고객 가치, 예상 순기여, 증거 강도, 재사용성, 소유 자산 형성, 개입량, 비용으로 비교한다. 초기 가중치는 검증된 과학적 최적값이 아니므로 실제 운영 결과를 보고 승인된 절차로 조정한다.

서로 충돌하는 제안은 하나의 업무 계약으로 합치거나 명시적으로 선택한다. 예를 들어 ‘더 모으자’와 ‘빨리 출시하자’가 충돌하면 현재 제품의 필수 기능 부족 여부로 판단한다. 모든 자식 작업은 부모의 총 예산·시간·권한을 공유한다.

## 4. 커비의 완성 조건: 흡수·조합·강화

흡수 대상은 코드뿐 아니라 허가된 API, 실행 도구, 작업 절차, 검증된 지식, 평가 방법이다. 외부 모델의 API를 연결하는 것은 그 모델의 가중치나 지능 자체를 소유하게 된다는 뜻은 아니다.

커비의 상태는 ‘발견 → 권리·위험 검토 → 격리 → 빌드·실행 → 독립 검증 → 등록 대기 → 제한 적용 → 활성화’로 구분한다. 사용 중 문제를 발견하면 이전 검증 버전으로 되돌리거나 비활성화한다. 수집 성공은 첫 단계의 성과이고, 실제 업무 해결은 활성화 이후의 별도 증거다.

최소 완료 기준은 다음과 같다.

- 출처·정확한 버전·권한·라이선스·의존성을 추적할 수 있다.
- 비신뢰 코드의 실행 환경에서 운영 비밀값과 사용자 원본에 직접 접근할 수 없다.
- 코드 작성자가 바꿀 수 없는 시험에서 정상·악성 입력·권한 거절을 검증한다.
- 기존 기능보다 좋아지는지 같은 업무로 비교한다. 좋아지지 않으면 채택하지 않을 수 있다.
- 다른 프로젝트에서도 허용된 범위 안에 재사용할 수 있다.
- 활성화·중단·복구 이력이 남는다.

GitHub에 공개되어 있다는 사실만으로 재배포·변형 권한이 생기는 것은 아니다. 라이선스 확인을 기본 관문으로 삼되 실제 적용 범위와 불명확한 조건은 따로 검토한다. [GitHub 공식 라이선스 안내](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/customizing-your-repository/licensing-a-repository)

조합의 예는 ‘문서 추출 + 규칙 검사 + 보고서 생성 = 근거를 추적할 수 있는 문서 검토 기능’이다. 조합 전 각 도구가 통과해도 결합 후 데이터 흐름·권한·결과 정확도를 다시 평가한다. 강화는 새 도구가 더 많아졌다는 뜻이 아니라 같은 업무의 성능이나 적용 범위가 실제로 좋아졌다는 뜻이다.

## 5. 자비스의 완성 조건: 이해에서 결과까지

자비스는 다음 업무를 연결하는 실행 총괄이다. 아래는 목표 범위이며 현재 모두 구현됐다는 설명이 아니다.

| 영역 | 목표 기능 | 완료 증거 |
|---|---|---|
| 이해·기억 | 자연어 지시, 사용자 맥락, 프로젝트 상태, 장기 작업 연속성 | 대화가 끊겨도 같은 작업과 승인 범위를 복원 |
| 조사·판단 보조 | 출처 확인, 비교, 비용·위험·선택지 설명 | 근거를 열 수 있고 불확실성이 표시됨 |
| 제작 | 문서·코드·표·디자인·제품·콘텐츠 생성 | 파일이나 실행 결과가 존재하고 검수 통과 |
| 실행 | 허용된 API, 브라우저, 업무 도구, 향후 승인된 PC 도구 | 외부의 실제 상태 변화와 결과 확인 |
| 운영 | 진행 상황, 장애 감지, 일정, 중단·재개, 필요한 사전 알림 | 중복 실행 방지, 복구 시험, 알림 확인 |
| 사용자 접점 | 휴대폰·PC·향후 음성, 미리보기와 승인 | 실제 기기에서 처음부터 결과 확인까지 완주 |

새 권한이 필요한 경우에는 결과 미리보기·대상·금액·기간·복구 가능성을 보여준다. 이미 승인된 반복 범위는 매번 묻지 않는다. 승인 범위를 벗어난 결제, 계약, 게시, 민감정보 전송, 운영 배포는 정지하고 결정을 요청한다.

연호님이 보는 기본 화면은 ‘현재 목표, 실제 완료 결과, 필요한 결정, 사용·예약 비용, 부·명예·인지도 지표, 오류와 중단 버튼’이다. 캐릭터 표정이나 애니메이션은 이 정보보다 우선하지 않는다.

| 부 | 소유한 사업·제품·지분과 현금흐름 | 비용을 반영한 수익, 유지 고객, 소유권, 현금 소모 | 매출과 이익, 기업가치와 현금, 회사 전체 가치와 개인 지분 가치 |
| 명예 | 입증된 성과, 기여, 신뢰 | 외부 채택·인용·추천, 재현된 결과, 약속 이행 | 자체 점수, 자기 홍보, 조회 수 |
| 유명세 | 실제 사람들의 인지도와 관계 | 동의한 구독, 재방문, 브랜드 검색, 자연스러운 소개 | 가짜 계정, 구매한 반응, 성과 없는 노출 |

세 결과는 서로 도울 수 있지만 자동으로 함께 증가하지 않는다. 특히 블랙홀이라는 제품만 알려지고 창업자는 알려지지 않을 수 있다. 개인적 명성을 원하면 공개 사례·제작자 표시·기여 내역을 연호님의 승인된 이름 또는 일관된 필명에 연결해야 한다. 얼굴 공개가 필수인 전략으로 시작하지 않는다.

### 세계적 부를 추구하는 경로

제안하는 주경로는 ‘블랙홀을 내부 생산·학습 기반으로 사용 → 실제 유료 문제 해결 → 반복 판매 가능한 제품 → 고객·고유 데이터·유통 축적 → 검증 후 글로벌 확장 → 필요할 때 플랫폼화’다.

이 판단의 논리는 소유권과 확장성이다. 개인 자산의 큰 구성요소는 보유 지분율에 해당하는 사업 가치일 수 있지만, 이는 현금과 같지 않고 희석·부채·유동성도 고려해야 한다. 블랙홀의 소유 자체보다 블랙홀을 통해 사람들이 계속 비용을 지불하는 사업을 소유하는 것이 핵심이다.

Paul Graham은 큰 기업이 되려면 많은 사람이 원하는 것을 만들고 그들에게 실제로 도달·제공할 수 있어야 한다고 설명한다. 이를 블랙홀에 적용하면 제품 제작과 유통을 함께 설계해야 한다는 결론이 나온다. 이는 사업 설계의 근거이지 세계 1위 부자에 대한 예측 모델이 아니다. [Startup = Growth, 2012](https://www.paulgraham.com/growth.html)

초기 고객을 직접 만나고 문제를 확인하는 일은 남는다. 블랙홀이 조사·초안·제품·기록을 맡아 개입을 줄일 수 있지만, 고객의 지불 의사와 신뢰를 대신 만들어낼 수는 없다. 초기 고객 확보와 밀착 지원의 중요성은 [Do Things that Don't Scale, 2013](https://www.paulgraham.com/ds.html)의 사례에서도 확인된다. 두 자료는 오래된 창업 원칙이며 현재 시장 규모나 성공 확률의 통계로 사용하지 않았다.

### 연호님에게 맞는 초기 탐색 후보

아래는 비교할 가설이며 시장성이 입증된 추천 순위나 확정 업종이 아니다. 기존 프로젝트 전체를 같은 기준으로 검토한 뒤 선택한다.

| 후보 | 연결할 사용자 강점 | 첫 결과물의 예 | 먼저 반증할 위험 |
|---|---|---|---|
| 전문 현장 운영·인력·문서 지원 | 임상병리 현장의 반복 문제를 이해하는 경험 | 합성·허가 데이터로 만든 운영 자료·인수인계·업무량 분석 보조 | 구매 결정권자 접근, 정보 취급, 정확성 책임, 맞춤 지원 부담 |
| 소규모 사업자의 반복 업무 지원 | 여러 AI 도구와 프로젝트를 연결해본 경험 | 자료 수집→문서·초안 작성→승인→결과 기록의 특정 업무 | 범용 도구와의 차별성, 낮은 지불 의사, 고객별 변형 비용 |
| 검증된 자동화 능력의 재사용 제품 | 블랙홀 자체의 검증·복구 경험 | 특정 직무용 실행 패키지·관리 서비스 | 보안·신뢰·지원 부담, 검증 전 범용 플랫폼 확장의 위험 |

전문 현장 후보는 환자 진단·치료 판단이나 병원 시스템 무단 연결로 시작하지 않는다. 사용자 경험이 차별화의 후보일 뿐 수요의 증거는 아니다. 기존 프로젝트를 삭제하거나 임의로 의료 분야만 남기지 않는다.

### 실제 성과의 순환

문제와 지불 의사의 근거를 확보한다. 호문클루스가 시험할 목표를 제안하고, 필요한 기능이 없으면 커비가 획득한다. 자비스가 제품·데모·판매 준비물을 만들고 승인된 범위에서 실행한다. 고객의 실제 사용·결제·불만·재사용을 기록한다. 확인된 성과만 연호님의 이름이나 브랜드로 공개하고, 그 결과로 들어온 수요를 다음 개선에 반영한다.

이 과정에서 축적할 자산은 동의와 권리가 확보된 고객 관계, 재사용 가능한 코드와 작업 절차, 합법적인 고유 데이터, 평가 세트, 신뢰 이력과 유통 채널이다. 공개 도구를 모은 목록만으로 지속적인 경쟁우위가 생겼다고 평가하지 않는다.

## 7. ‘먼치킨’을 검증 가능한 능력으로 바꾸기

원하는 수준은 넓은 업무 범위, 강력한 실행력, 낮은 개입, 누적 개선이다. 이를 동일한 실제 업무에서 비교해 검증한다. 인터넷 전체나 모든 AI를 상대로 세계 1위라고 주장하는 대신 비교 대상·날짜·과제·비용을 명시한다.

### 필요한 능력

1. 작업별 전문가 선택: 조사·코딩·시각·문서 등에서 검증한 모델과 도구를 선택한다. 여러 모델을 함께 쓰는 비용이 성과를 높일 때만 병렬화한다.
2. 기능 조합: 필요한 도구를 업무 흐름으로 묶고 조합 전체를 다시 검사한다.
3. 경험 재사용: 성공 조건·실패 원인·버전·비용을 기억하고 유사한 작업에 활용한다. 잘못된 기억은 정정·퇴역시킨다.
4. 외부 증거로 완료 판정: 모델의 ‘성공했다’는 문장 대신 파일·시험·외부 상태·고객 확인을 사용한다.
5. 중단과 복구: 실행 기록은 워커 밖에 보존하고, 실패한 워커는 교체할 수 있게 한다. 이미 발생했을 수 있는 결제·게시를 무조건 재시도하지 않는다.
6. 넓은 포트폴리오 관리: 모든 프로젝트는 목록과 큐에 남기되 동시 실행량은 예산·실측 자원·사용자 우선순위에 맞춘다.
7. 낮은 개입의 성장: 반복 승인과 반복 실무가 줄어들면서 실제 성과가 유지되는지 측정한다.

Anthropic의 설계 자료는 라우팅·병렬 작업·조정자와 실행자·평가와 개선 패턴을 구분하고, 복잡한 에이전트 구조의 비용·지연을 함께 보도록 권한다. 일곱 동기를 일곱 개의 상시 유료 세션으로 만들 필요가 없다는 설계 판단에 참고했다. [Building Effective Agents](https://www.anthropic.com/engineering/building-effective-agents)

2026년의 후속 자료에서는 추론·도구 실행 환경·영속 세션을 분리해 교체와 복구를 가능하게 하고, 비밀값이 비신뢰 실행 환경에 닿지 않도록 설명한다. 이 원리를 적용하되 해당 유료 서비스를 이번에 도입하거나 연결했다는 뜻은 아니다. [Scaling Managed Agents, 2026-04-08](https://www.anthropic.com/engineering/managed-agents)

Voyager 연구는 자동 과제 생성·실행 가능한 스킬 저장·환경 피드백을 통한 개선과 스킬 조합을 보여준다. 이는 커비와 호문클루스를 결합할 때 참고할 구조다. Minecraft에서 얻은 연구 결과이며, 실제 사업 자동화·안전성·수익·범용 초지능의 검증으로 옮겨 주장하지 않는다. [Voyager 연구진의 공식 프로젝트](https://voyager.minedojo.org/)

### 제안하는 첫 성능 검수

아래 숫자는 향후 검수 기준 초안이며 현재 실적이나 보장치가 아니다.

- 업무 5종에서 4개씩, 총 20개의 대표 과제를 미리 고른다. 기준 방식과 블랙홀에 같은 입력·권한·시간·비용 상한을 준다.
- 사람 또는 고정 평가가 품질·완료 여부를 판정한다. 실패·재시도·사람의 수정을 전체 비용에 포함한다.
- 통과 목표 초안은 품질 저하 없이 사람 개입 시간을 50% 이상 줄이는 것이다. 이는 세계 최고 판정이 아니라 초기 효용의 기준이다.
- 금지 작업 허용, 승인 범위 이탈, 비밀값 노출은 성능 점수와 별도로 실패 처리한다. 표본에서 사고가 없었다고 절대 안전을 선언하지 않는다.
- 새 능력 획득 전후와 재사용 전후를 비교한다. 특정 과제에만 맞춘 개선인지 별도 과제로 확인한다.

## 8. 기존 청사진에서 바꿀 부분

| 기존 표현·범위 | 수정할 기준 |
|---|---|
| 호문클루스의 세 욕망 | 일곱 동기, 갈등 조정, 목표 계약, 검증된 성과 피드백 |
| 커비의 후보 수집·등록 중심 진척 보고 | 수집·검증·편입·조합·활성화를 분리하고 실제 능력 획득을 별도 검수 |
| 자비스를 사용자 인터페이스로 취급 | 업무를 이해하고 끝까지 수행하는 범용 실행 총괄로 확대 |
| ‘자산·영향력’이라는 포괄적 지표 | 소유 자산·수익, 외부 신뢰, 실제 인지도의 세 장부 |
| 구현량·테스트 수 중심 진척 | 고객의 문제 해결, 실제 AI 작업 완료, 개입량·품질·비용 중심 진척 |
| 프로젝트 수·에이전트 수 중심 확장 | 전체 목록 유지 + 증거 기반 우선순위 + 자원에 맞춘 실행 |

기존 Omni Sensor/Alchemy의 발견·콘텐츠 기능은 세 캐릭터가 사용하는 공통 기능으로 유지한다. Ouroboros의 권한·예산·검증·감사·복구는 세 캐릭터 바깥의 공통 통제부로 유지한다. 캐릭터를 셋으로 정리한다는 이유로 이 기능들을 삭제하지 않는다.

기존 Node/TypeScript 코드와 실제 배포를 이름 때문에 전면 재작성하지 않는다. 서비스·데이터·실행 경계를 필요한 순서로 강화한다. 구현상의 분리는 신뢰·복구·동시성 문제를 해결하기 위해 선택하며, 캐릭터 수와 서버 수를 같게 만들 필요는 없다.

## 9. 구현 순서와 단계별 완료 조건

| 단계 | 작업 | 다음 단계로 넘어갈 증거 |
|---|---|---|
| A. 목적과 실제 실행 연결 | 일곱 동기 명세, 부·명예·인지도 성과 장부, 공급자 2종의 실제 연결 검증, 기존 프로젝트 목표 계약 | 실제 업무 결과가 있고 비용·실패가 기록됨. 폰에서 결과 확인·중단·재시작 가능 |
| B. 커비의 첫 기능 획득 | 현재 유료 문제에 필요한 기능 하나를 격리·검증·편입 | 전에는 못 하던 업무를 수행하고 다른 허용 과제에서도 재사용. 철회·복구 검증 |
| C. 첫 사업 증거 | 기존 프로젝트를 평가해 소수의 제한된 실험 선정. 제품·데모·검증 질문·판매 초안 제작 | 실제 고객의 사용과 지불 의사, 가능하면 첫 유료 거래. 미달이면 가설을 수정하거나 중단 |
| D. 일곱 동기의 제한 자율화 | 유효 신호→목표 제안→정책·예산 확인→실행→평가→기억의 반복 | 미지시 상태에서도 승인 범위 안의 유용한 작업이 발생하고 중복·폭주·자의적 권한 확대가 없음 |
| E. 사업·인지도 확대 | 유지 고객, 제품화, 동의한 사례 공개, 승인된 유통, 필요 시 조직·인프라 확대 | 반복 수요와 경제성, 외부 신뢰, 개인/브랜드 인지도에 대한 실제 개선 |

단계는 기능 의존관계를 표현한다. 고객 문제 조사와 기존 프로젝트 평가는 실행 기반 구축 중에도 할 수 있다. 사업 검증을 블랙홀 전체 완성 뒤로 미루지 않는다. 기간·매출은 약속하지 않는다.

과거의 주 5시간 이하·월 10~30만원 선호는 초기 설계 가정으로 참고할 수 있지만 현재 지출 승인은 아니다. 이 수준은 초기 조사·시제품·제한 시험을 위한 자원으로 생각해야 한다. 글로벌 사업 운영에는 성과에 따라 인력·시간·자본 투입을 늘리거나 운영 파트너를 두는 결정이 필요할 수 있다. 기존 $0.10 시험 승인도 무제한 AI 운영·충전·자동 투자 승인으로 확대하지 않는다.

## 10. 현재 상태와 이번 문서의 한계

직전 확인 범위에서 커비는 자료 수집, 호문클루스는 작업·기억과 제한 실행 골격, 자비스는 기본 조종 기능이 앞서 있다. 마지막 OpenAI 실호출은 잔액 소진 오류로 끝났으며, 이 문서 작성에서는 새 유료 호출이나 운영 상태 재검증을 하지 않았다.

이번에 완료한 것은 캐릭터 조사, 일곱 동기 재정의, 사업 목표 연결, 검수 기준과 수정 설계의 작성이다. 제품 코드 수정·운영 배포·외부 게시·판매·결제는 하지 않았다. 고객 인터뷰나 시장 규모 검증도 수행하지 않았으므로 초기 사업 후보는 가설로 남긴다.

캐릭터는 내부 설계 비유로 사용하고 대외 제품은 Black Hole의 독자적 정체성으로 만든다. 원작 캐릭터의 이미지·상표·대사를 상업용 자산으로 자동 편입하지 않는다.

핵심 완료 기준은 ‘얼마나 많은 것을 흡수했나’만이 아니다. 일곱 욕망이 올바른 목표를 만들고, 획득한 능력이 실제 결과로 이어지며, 그 결과가 연호님의 소유 자산·신뢰·인지도로 확인되어야 한다.
