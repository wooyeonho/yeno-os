# CODEX 지시서 — JARVIS 비주얼 업그레이드 (2026-09-27)

작성: Claude(Cowork). 배경: 소유자가 오픈소스 "아이언맨 자비스" 클론들과 비교해서 현재 화면(정적 2D 캔버스 오브)이 평면적이라고 지적함. 언리얼 엔진 사용 여부도 물어봄.

## 0. 언리얼 엔진 기각 사유 (먼저 정리)

**쓰지 않는다.** 이유:
- 언리얼은 네이티브 게임 엔진이다. 지금 BLACKHOLE은 Node.js 서버(`runtime/server.mjs`) + 브라우저(`runtime/public/*.mjs`) + Android 컨트롤러(Tauri) 구조인데, 언리얼을 쓰려면 이 전체를 다시 짜야 한다 — 기존에 돌아가는 걸 다 버리는 것과 같다.
- 언리얼을 브라우저/폰에서 보여주려면 픽셀 스트리밍(서버가 실제로 3D를 렌더링해서 영상으로 스트리밍)이 필요한데, 이건 GPU 서버가 상시 돌아야 하는 구조다. 지금 PC는 RAM 7.7GB짜리 로컬 머신이고, 이미 RAM 부족으로 여러 차례 막혔던 이력이 있다(§61-71). 언리얼 픽셀 스트리밍용 GPU 서버 비용/운영 부담을 추가하는 건 지금 상황과 정반대 방향이다.
- 목표(오브 + 홀로그램 링 + 반응형 애니메이션)는 언리얼 없이도 브라우저 기술로 충분히 도달 가능하다.

## 1. 대신 쓸 것: Three.js (WebGL)

이유: 지금 이미 브라우저에서 `<canvas>` 2D로 오브를 그리고 있다(`runtime/public/jarvis-orb.mjs`, §78에서 분리됨). Three.js는 같은 브라우저 안에서 2D canvas 대신 WebGL 3D를 쓰는 라이브러리라 서버/배포 구조를 하나도 안 건드리고 교체 가능하다. 실제로 검색된 오픈소스 자비스 클론들 대부분이 이 방식을 쓴다 (Three.js Journey의 hologram shader, Anderson Mancini의 vanilla holographic material 등이 참고 가능한 공개 기법).

## 2. 구체적 변경 범위

파일: `runtime/public/jarvis-orb.mjs` (현재 104줄, 2D canvas 기반) → Three.js 기반으로 교체.

- CDN: 프로젝트의 "로컬 독립 실행" 원칙(§0.1)과 충돌 여부부터 확인할 것. `three.min.js`는 `runtime/public/vendor/`에 로컬로 내장한다. 외부 CDN 실시간 로드는 금지 (오프라인 원칙 위반 가능).
- 오브: 구체(SphereGeometry) + 커스텀 GLSL 프래그먼트 셰이더로 프레넬(가장자리 발광) 효과. 기존 시안/블루 팔레트(`--cyan` 계열, §5 대비율 기준 유지) 그대로 사용.
- 홀로그램 링: 기존 정적 동심원 대신, 3개 이상의 토러스(TorusGeometry) 링을 서로 다른 속도로 천천히 회전시켜 깊이감을 준다.
- 반응형: 기존 상태머신(§75 정의 6개 state: idle/thinking/speaking/approvalPending 등)에 따라 오브 스케일·발광 강도·링 회전속도가 바뀌도록 — 새 상태를 만들지 말고 기존 상태 값을 입력으로만 쓴다.
- `prefers-reduced-motion`: 기존 캔버스 버전이 처리하던 접근성 조건(§75)을 Three.js 버전에서도 유지 — 애니메이션 끄고 정적 프레임만 표시.

## 3. 성능/제약 — 반드시 지킬 것

- 이건 브라우저(클라이언트) GPU에서 돌아가는 것이라 PC의 7.7GB RAM/로컬 LLM 자원과는 무관함. 다만:
  - 저사양 안드로이드 폰(컨트롤러 앱)에서도 열리므로, 모바일 프레임드랍/발열 실측 확인 필수.
  - WebGL 컨텍스트 생성 실패(구형 기기, 소프트웨어 렌더링 환경) 시 기존 2D canvas 버전으로 자동 폴백 — 이 폴백 경로 자체가 테스트 항목. 지금 있는 2D 버전을 삭제하지 말고 폴백용으로 보존.
- CSP(server.mjs 보안 헤더, 기존 §0 계약)의 script-src 정책과 로컬 번들 파일 경로가 충돌 없이 통과하는지 확인.

## 4. 인수 기준

- V1: 실제 브라우저(데스크톱 크롬) 스크린샷 — 회전하는 3D 링이 육안으로 확인되는 정지 프레임 2장(0초/2초 시점) 이상 차이 — 회전 증거.
- V2: 모바일 폭(400px)에서 프레임레이트 실측 — 최소 30fps 유지 로그.
- V3: `prefers-reduced-motion: reduce` 강제 설정 시 회전 정지 스크린샷.
- V4: WebGL 비활성화 강제 상태에서 2D 캔버스 폴백이 실제로 뜨는 스크린샷.
- V5: 기존 §75-79 A1-A12 회귀가 깨지지 않았는지 재실행 결과.
