# 실제 개발 상태 — 2026-09-09

## 이번 구현 결과

- 수정 전 `runtime/` 0.1.1의 기준선 20개 파일 무결성을 확인했고 기존 19개 검사가 모두 통과했다.
- 코어를 0.2.0으로 확장했다. 기존 `/api` 호환 경로는 유지하면서 네이티브 앱용 `/api/v1` 계약, 페어링 토큰과 분리된 기기별 토큰 발급, 재시작 후 인증 유지, 자기 기기 폐기를 구현했다.
- 기존 상태 파일에는 `devices`를 추가하는 보존형 마이그레이션을 적용했다. 단일 프로세스 JSON 저장소라는 제약은 그대로이며 운영 동시 확장 준비가 끝났다는 뜻은 아니다.
- `apps/controller`에 Tauri 2 Android 우선 controller 소스를 구현했다. 명시적 코어 주소, 원격 HTTPS 강제, 암호로 잠긴 native Stronghold 보관소, 지속 request ID, 명령/상태/결과, 일시정지/재개/취소/전체 멈춤 화면이 포함된다.
- 코어 통합 검사는 신규 기기 등록·재시작·폐기까지 포함해 20개가 통과했다.

## 빌드와 검증 상태

- 이 환경의 실제 Node는 v20.20.2여서 선택 기준 Node 24와 다르다. 코어 검사는 통과했지만 Node 24 재확인이 필요하다.
- Rust 1.89.0, Cargo 1.89.0, JDK 21.0.2는 확인했다.
- npm registry의 Tauri 패키지 요청이 HTTP 403으로 차단되어 의존성 설치와 TypeScript/Tauri 빌드를 실행하지 못했다.
- Android SDK/NDK 환경 변수와 `adb`, `sdkmanager`가 없어서 Android 프로젝트 생성과 APK 빌드를 실행하지 못했다. APK 결과 파일은 없다.
- 앱 소스가 구현됐다는 것과 APK 빌드·설치·실기기 동작은 구분한다. 실제 폰, 운영 HTTPS 주소, 공개 배포, 유료 모델 공급자는 연결하거나 검증하지 않았다.

## 다음 한 작업

Node 24, npm registry, Android SDK/NDK를 사용할 수 있는 빌드 실행 환경에서 `docs/ANDROID_BUILD.md` 순서로 APK를 만들고, 영속 HTTPS 코어 주소를 연결해 `docs/DEVICE_ACCEPTANCE.md`의 실기기 절차를 수행한다.

## 버전 구분

이번 저장소 코어는 0.2.0 후보이며 이전 노트북의 별도 0.2.3 설치를 읽거나 덮어쓰거나 마이그레이션하지 않았다.
