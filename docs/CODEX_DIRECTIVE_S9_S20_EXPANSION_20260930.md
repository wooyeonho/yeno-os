## S9. 진짜 측정 — 네 가지 빈 칸을 실제 세상에 연결

**사실**: `motivation.mjs MISSING_MEASUREMENTS = ['revenue','audience','independent_research_validation','owner_result_rating']`. `outcome-verification.mjs`에는 이미 원장(wealth/honor/fame/adoption), 지표(`wealth.revenue`, `adoption.installs`, `fame.followers` 등), 출처 유형(payment_processor, analytics_platform, publication_platform…), 권한(`TYPE_AUTHORITY`: 모델은 결코 결과의 권한이 아님)이 정의돼 있다. **새 지표·원장·권한을 만들지 말고 이 계약에 실제 출처를 연결한다.**

- **S9-a 소유자 평가(owner_result_rating)**: 자비스가 결과를 보여줄 때 한 번의 터치로 1~5 별점을 받는다(`verificationType:'self_reported'`, `authority:'owner'`, 출처 `owner_report`). 미평가는 null, 자동 채움 금지. 평가는 욕망 v3 정산을 바꾸지 않고 **별도 열**로만 기록한다(선언 정책과 소유자 감정을 섞지 않음).
- **S9-b 청중(audience)**: 커넥터 패널에 `analytics`·`publication` 종류 추가. 첫 범위는 소유자가 실제로 쓰는 플랫폼 중 **공식 읽기 전용 API가 있는 것 1개**(GitHub 저장소 stars/watchers는 이미 근거 검증기 경로가 있으니 `adoption`의 최소 출처로 재사용). `external_structured` + `authority:'external'`. 응답 원문 SHA-256·fetchedAt 보존.
- **S9-c 수익(revenue)**: 결제·정산 플랫폼의 **읽기 전용** 공식 API만. 소유자가 커넥터 패널에서 선택하고 키를 직접 입력하기 전까지 `not_implemented`/`needs_owner`. 금액은 절대 화면에 추정치로 채우지 않는다. 송금·거래 기능은 만들지 않는다(구현 자체 금지).
- **S9-d 독립 검증(independent_research_validation)**: `external_verified`는 `external_attested`만 가능. S15 공개 영수증 페이지의 제3자 서명 절차가 생기기 전까지는 항상 비어 있음을 화면에 명시.
- **연결**: 네 값이 채워지면 `MISSING_MEASUREMENTS`에서 해당 항목이 결정별로 빠지고, 후보 순위(`scoreMotivation`)는 **바꾸지 않되** 결정 기록에 "측정 가능" 표시가 붙는다. S등급 조건(`solo-leveling` 외부 검증 고등급)은 동결 파일 무수정 그대로 — 새 증거가 기존 계약을 통과하는지만 시험.
- **시험**: 출처 유형 허용표 위반 거부, 모델 출력이 권한이 될 수 없음, 소유자 별점 자동 채움 금지, 응답 해시 재검증, 429·타임아웃 unknown 처리.
- **수용**: 실제 출처 1개(어댑션 또는 청중)가 실측값으로 원장에 기록되고, 나머지는 BLOCKED/needs_owner로 정직하게 표시.

## S10. 밤 주기 — 잠과 꿈

- 상주(`resident.mjs`)에 소유자가 시간대를 정하는 **야간 창**(기본 미설정 = 꺼짐). 창 안에서만 도는 나태 주도 정리 주기. 새 스케줄러를 만들지 말고 기존 durable job과 예산을 쓴다.
- 작업(모두 모델 호출 0 또는 로컬 전용): 분노=실패 작업 재생 목록 작성(같은 공개 오류 코드 묶음), 폭식=오래된 근거 만료 표시(G1 `expireStaleGaps` 재사용), 강욕=중복 산출물 해시 병합 후보 목록(삭제 금지, 목록만), 나태=재사용 가능한 능력 목록 갱신, 색욕=자기 미화 초안 정리.
- 아침 보고: 자비스 격식체로 "밤사이 보고" 1건을 시스템 알림(E4)과 Obsidian `01_DRAFTS/BLACKHOLE_연대기/YYYY-MM-DD.md`에 저장(Obsidian REST 커넥터가 `connected`일 때만, 아니면 로컬 파일 + BLOCKED 표시). 연대기는 실제 기록만 투영, 없는 사건 생성 금지.
- 시험: 창 밖에서 실행 0, 창 안에서 모델 호출 0, 재시작 중복 0, 연대기 파일 해시가 기록과 일치.

## S11. 그림자 = 실제 개별 에이전트

**사실**: `shadow-army.mjs`는 역할 프롬프트와 `dependsOnJobIds`로 정찰·연구·건설→검증→의미검증 체인을 이미 만든다. C2가 끝나면 그림자는 이름·계급·보관 상태를 가진 기록이다.

- 각 그림자에 **실행 프로필** 추가: `{modelBinding, toolScope, budgetShare}`. `modelBinding`은 커넥터 패널의 `connected` 추론 커넥터 중 하나(로컬/클라우드 혼합 허용, 소유자가 화면에서 배정, 기본은 기존 에이전트 설정 상속). `toolScope`는 역할별 고정 허용 목록: 정찰자=검색·읽기 전용 브라우저, 연구자=근거 검증기·Vault 읽기, 건설자=코드 작성(정적 가드 통과 필수), 검증자=실행 없이 판정만, 의미검증자=판정만.
- 계급 승급 시 `toolScope`가 정해진 표대로만 넓어진다(예: 일반병 정찰자는 검색 1회/미션, 대원수는 예산 안에서 반복). **표는 선언 정책**이고 승급 조건은 동결된 등급 계약을 그대로 쓴다.
- 그림자 간 **작업 인계**는 기존 `dependsOnJobIds`로만. 그림자가 다른 그림자의 도구 범위를 빌릴 수 없다.
- 시험: 역할 밖 도구 호출 거부, 배정되지 않은 커넥터 사용 거부, 승급 전후 범위 표 일치, 보관(stored) 그림자는 실행 불가.
- 수용: 실제 격리 코어에서 정찰(로컬 모델)→검증(다른 모델) 체인이 서로 다른 `modelBinding`으로 1회 완주(합성/실증 표시).

## S12. 자비스의 몸 — 편재

- **음성 입력**: whisper.cpp(MIT) 로컬 서브프로세스 커넥터(`voice` 종류, 루프백·파일 입력만). **음성 출력**: Piper 후계는 GPL-3.0이므로 **별도 프로세스 전용**으로만, 브라우저 음성은 기본 대체. "숨기지 않겠습니다" 문구는 음성에서도 삭제·축약 금지.
- **텔레그램**: 기존 `persistent-bots.mjs` 경로 위에 소유자 전용 봇(토큰 소유자 입력). 읽기: 상태·밤사이 보고·검토 대기 초안 수. 쓰기: 초안 승인/거절·미션 시작만. 실행 코드 활성화는 텔레그램에서 **불가**(화면 승인 문만).
- **안드로이드**: `apps/controller` 기존 앱에 같은 읽기/제한된 쓰기 API. 실기기 검증은 ADB 연결 시에만, 아니면 BLOCKED.
- **브라우저**: `openclaw-bridge.mjs`(후보 분류 전용)를 정찰자 `toolScope`에만 연결. 페이지 내용은 데이터로만 취급, 페이지가 지시하는 행동 금지.
- 시험: 채널별 권한 표(무엇을 못 하는지 포함), 토큰 미출력, 재시작 후 웹훅 중복 0.

## S13. 능력 교환소

**사실**: `capabilities.mjs`는 매니페스트 import→verify→activate, 해시·이전 해시·복원을 이미 가진다.

- **내보내기**: 활성 능력을 `{manifest, versions[].hash, verification history, license, source}`로 서명(ed25519, 키는 소유자 DPAPI)해 파일로 저장.
- **가져오기**: 서명 검증→`absorb-inbox`의 새 kind `'exchanged-capability'`로만 진입(승격 함수 없음)→소유자 검토→기존 import→verify→activate. 정적 가드 통과 필수. 서명자 신뢰 목록은 소유자가 화면에서 관리.
- 교환 자체에 네트워크 서버를 두지 않는다(파일 교환). 공개 인덱스는 S15 이후.
- 시험: 위조 서명 거부, 매니페스트 변조 거부, 신뢰 목록 밖 서명자 거부, 가져온 능력이 승인 전 실행 불가.

## S14. 공개 영수증 페이지

- 미션이 끝나면 `receipts/<missionId>.html` 정적 페이지 1개 생성: 입력 해시, 모델 바인딩(모델명만, 키 없음), 각 단계 산출물 해시, 검증 판정, 욕망 논쟁 기록, 합성/실증 표시. 페이지는 **기록에서만** 생성되며 편집 불가(해시 체인: 직전 영수증 해시 포함).
- 공개는 소유자가 페이지 단위로 명시 승인할 때만(기본 비공개, 로컬 파일). 개인 목표 원문·Vault 내용·오류 원문은 포함하지 않고 공개 오류 코드만.
- 재검증 스크립트 `scripts/verify-receipt.mjs` 동봉: 누구나 산출물과 페이지로 해시 체인을 다시 계산.
- 시험: 체인 끊김 감지, 비밀 문자열 0, 개인 정보 필드 0, 재검증 스크립트가 변조를 잡음.

## S15. 제3자 검증 절차 (S등급의 진짜 의미)

- `external_verified` / `authority:'external_attested'`를 채우는 유일한 길: 검증자가 S14 영수증을 재검증하고 서명(ed25519)한 `attestation` 파일을 가져오기. 서명자 신뢰 목록은 S13과 공유.
- 최소 1명의 외부 검증자(소유자가 아닌 사람)가 1건을 실제로 서명하기 전까지 화면은 "외부 검증 0건"을 그대로 보여준다.
- 동결된 `solo-leveling.mjs`의 S등급 조건은 무수정 — 새 attestation이 기존 계약을 통과하는지만 시험.

## S16. 자기 개선 제안 루프 (승인 문 유지)

- 입력: C1 자기 미화 초안, G1 흡수 초안, 욕망 v3 stuck, 밤 주기 실패 재생 목록.
- 출력: `absorb-inbox` 새 kind `'self-change-proposal'` = {대상 파일, 변경 이유(실제 기록 링크), diff, 정적 가드 결과, 관련 fast 테스트 결과}. 제안은 격리 작업 복사본에서만 만들고 실제 트리에 쓰지 않는다.
- 소유자가 화면에서 승인하면 그때만 실제 트리에 적용 + 관련 테스트 + 기록. 동결 3파일과 이 지시서의 불변 조건을 건드리는 제안은 **생성 단계에서 거부**.
- 시험: 동결 파일 대상 제안 거부, 정적 가드 실패 제안은 초안 불가, 승인 없이 트리 무변경.

## S17. 무대 — 세계 1위 UI

- 대시보드가 아니라 **장면**: 일곱 욕망이 실시간 발언(E2 대사)하고 허기(v3)가 움직이며, 정산 순간·그림자 기상·커비 흡입·자비스 오브 상태가 모션으로 보인다. 소리는 소유자 토글(기본 꺼짐).
- 디자인 시스템 파일(`runtime/public/DESIGN.md` 확장): 색 토큰(라이트/다크), 타이포, 간격, 모션 지속시간 표, 접근성(색 없이 읽힘·400/768/1440·키보드).
- **공개 브랜드 층 추가**: 화면·문서에 `brandName` 토큰을 두고, 내부 개념명(커비·그림자·자비스 등)은 코드·내부 문서에 유지하되 공개 화면은 토큰을 통해 우리 이름으로 표시. 소유자가 이름을 정할 때까지 토큰은 "BLACKHOLE"만.
- 90초 데모 장면: 실제 격리 코어 기록으로 녹화(합성/실증 자막 표시). 지어낸 장면 금지.
- 시험: 기존 UI 테스트 유지 + 모션 꺼짐 모드에서 정보 손실 0, 소리 꺼짐 기본.

## S18. 설치와 인프라 — 한 대 PC를 벗어나기

- Windows 설치 파일(기존 상주·작업 예약 재사용)과 자동 업데이트 확인(다운로드는 소유자 승인 후). 서명은 소유자 인증서.
- 두 번째 실행 머신 지원: 커넥터 패널에 `remote-runner`(소유자 소유 머신, 루프백/SSH 아님 — HTTPS 상호 인증) 종류. 원격 머신은 건설자·정찰자 작업만, 상태 저장은 주 머신.
- CI: GitHub Actions에 fast/integration 층 실행(기존 워크플로 확장). full은 야간 수동.
- 충돌 보고: 로컬 파일로만, 비밀 0, 소유자가 보내기 전엔 전송 없음.
- 시험: 설치→상주 시작→상태 API 응답, 업데이트 위조 서명 거부, 원격 러너 권한 표.

## S19. 사업 층 (코드 범위만)

- **라이선스 키**: 오프라인 서명 검증(ed25519), 기능 게이팅은 편재(S12)·교환소(S13)·원격 러너(S18)에만. 핵심 엔진·검증·영수증은 게이팅하지 않는다(신뢰가 상품이므로).
- **영수증 검증 API**: S14 재검증을 로컬 HTTP(루프백)로 제공. 외부 노출은 소유자가 별도 설정으로만.
- **연대기 내보내기**: S10 연대기를 마크다운/EPUB로 묶는 스크립트(작가 소유자의 연재용). 실제 기록만, 생성 문장은 "연대기 서술" 표시.
- 결제·계정 생성·송금 기능은 만들지 않는다.

## S20. 공개 준비 — 신뢰 장치와 재현 번들

- 재현 번들: 임의 미션 1건의 입력·산출물·영수증·재검증 스크립트를 zip으로 묶고 해시 목록 동봉.
- "주장 대 영수증" 표: README에 기능별 실증/합성/미구현 상태를 기계가 읽는 `docs/STATUS.json`에서 생성(수동 편집 금지, 실행 기록에서 파생).
- 공개 README(외부인 5분 이해), 라이선스 파일(핵심 관대한 라이선스, GPL 구성요소는 별도 프로세스 표기), 기여 규칙(불변 조건 그대로), 보안 신고 경로.
- 외부 테스터 10명용 설치 안내와 피드백 양식(로컬 파일, 전송은 테스터가 직접).
- 수용: 재현 번들을 제3자가 다른 머신에서 재검증 성공 1건(BLOCKED면 그대로 표시).
