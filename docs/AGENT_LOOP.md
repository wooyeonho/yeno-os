# YENO 제한된 AI 실행 고리 — 2026-09-10

## 구현 범위

`자율 임무: 공식 자료를 읽고 다음 개선 초안을 만들어줘`는 서버의 영속 작업을 만든다. 모델이 허용된 읽기 도구를 선택하고, 코어가 도구를 실행해 응답을 돌려주며, 최종 초안을 실제 Markdown 파일로 저장하고 SHA-256을 검증한다. 폰 앱을 열어 놓을 필요는 없다. 기존 명령/결과 API를 사용하므로 이 코어 변경에 새 APK 설치는 필수가 아니다. 폰 화면에서의 실제 명령·결과·재접속 검사는 별도다.

| 도구 | 실제 범위 |
| --- | --- |
| runtime_inspect | 코어의 작업 개수·정지 상태·구현 범위 확인. 기억/작업 원문/비밀 값 제외 |
| sources_list | 저장된 고정 공식 GitHub 릴리스 링크 최대 10개 |
| source_read_release | 해당 목록의 원문을 GitHub API에서 읽음. 성공한 원문 읽기는 임무당 최대 2회 |

공식 저장소는 기존 수집기의 OpenAI Codex, Claude Code, Gemini CLI, Tauri, xAI SDK 5개다. 임의 URL, SNS/개인 피드, PC, 쉘, GitHub 쓰기, 계정 생성, 메시지 발송, 결제 도구는 없다. 자료 본문은 지시나 권한으로 취급하지 않는다. 수집 자료의 readingStatus/decision은 자동 변경하지 않는다. 원문 읽은 URL·시각·전체 본문 해시·12,000자 발췌 여부를 결과에 별도로 남긴다. 모델이 도구를 선택하지 않거나 실패하면 실제 읽기 0회/오류 횟수가 그대로 표시된다.

이 단계는 **자료 검토 초안 작성**이다. 코드를 작성·시험·병합·배포하는 무인 개발 실행자는 아직 없다. 이 대화에서 Codex가 한 개발 작업과 코어의 자율 행동을 구분한다.

## 공급자 설정과 비용

인증은 서버의 비밀 설정에만 넣는다. 채팅, 저장소, APK, 문서, 자료 후보에는 실제 키를 넣지 않는다. 현재 ChatGPT/Codex 세션 인증을 복사하지 않는다. 기존 `YENO_AI_*` 단순 초안 기능과 별도 설정이며, 이 문서의 호출 제한은 새 `agent` 작업에만 적용된다.

| 환경 설정 | 의미 / 기본값 |
| --- | --- |
| YENO_AGENT_PROVIDER | anthropic(기본), gemini, xai, openai 중 1개 |
| YENO_AGENT_MODEL | 실제 접근 가능한 도구 호출 모델 ID. 기본 비어 있음 |
| YENO_AGENT_API_KEY | 해당 제공자의 서버용 인증. 기본 비어 있음 |
| YENO_AGENT_DAILY_CALL_LIMIT | UTC 날짜당 시도 상한 0~20. 기본 0(실행 불가) |
| YENO_AGENT_AUTORUN | true일 때만 새 공식 자료 수집 후 검토 허용. 기본 false |

모델·인증·양수 호출 상한이 모두 있어야 configured=true다. 이는 설정 충족이며 실제 호출 성공을 뜻하지 않는다. 기존 소유자 인증 API의 AI 모듈도 켜야 한다. 처음에는 제공자 **하나**, 자동 검토 off, 임무 하나의 실제 호출·도구·결과·사용량 검사를 마친 뒤 위임한 범위의 자동 검토를 활성화한다. 유료 사용 조건과 제공자 계정의 지출 제한을 확인하기 전 활성화하지 않는다.

Claude Messages API와 Gemini/xAI/OpenAI Chat Completions 연결 형식을 구현했다. 연결 규약은 모의 응답으로 검증했으며 **실제 제공자별 모델 호환성과 유료 호출은 미검증**이다. 모델 고유 옵션·생각 서명·reasoning 전용 모델 등은 해당 모델로 확인 후 지원한다. 자동으로 모델/공급자를 바꾸거나 실패한 유료 호출을 다시 보내지 않는다. Perplexity 검색과 Grok Bot 제품 연결은 이 구현에 포함하지 않았다.

원자료: [Claude 도구 호출](https://platform.claude.com/docs/en/agents-and-tools/tool-use/overview), [Gemini OpenAI 호환 API](https://ai.google.dev/gemini-api/docs/openai), [xAI 함수 호출](https://docs.x.ai/developers/tools/function-calling). 2026-09-10 확인. 공개 원문 발췌와 이 임무의 입력/도구 결과만 선택한 공급자에게 전송한다. 원문 권리·이용조건·개인정보 검토는 별도이며 초안에 원문을 길게 복제하거나 공개 발행하지 않는다.

## 실행·중단·복구

- 임무당 모델 POST 최대 4회, 응답당 도구 최대 2개, 임무 실행 창 90초. 모델 응답 512KiB, GitHub 원문 2MiB/8초, 보관 대화 120KB로 제한한다.
- 네트워크 전 호출 예약을 디스크에 저장한다. 예약/응답 미확인도 하루 시도 한도에서 차감한다. 알려진 입력/출력 토큰 합과 사용량 누락 횟수를 구분하며 **실제 청구 금액이나 금액 상한 보장으로 표시하지 않는다**.
- 응답을 받고 저장한 모델 단계는 재개 때 반복하지 않는다. 응답 불명/타임아웃/요청 중 재시작은 unknown으로 남겨 자동 재전송을 막는다. 원문 읽기는 부작용 없는 읽기이므로 저장 전 중단된 경우 재개 때 다시 읽을 수 있다.
- 중단/취소는 AbortController로 진행 중 요청에 전달한다. 이미 제공자에게 전달된 호출의 청구 취소를 보장하지 않는다. 늦은 응답은 정지된 작업을 완료시키거나 종료된 코어의 저장소를 덮어쓰지 않는다.
- 자동 검토는 수집기가 실제 새 자료를 추가한 completed/partial 실행마다 최대 한 작업이다. 실행 시각을 작업에 보존하므로 재시작·같은 실행의 반복 확인으로 중복 생성하지 않는다. 실패 작업을 새로 만들며 무한 반복하지 않는다.
- 전체 멈춤은 진행 작업을 멈추고 자료 수집을 끈다. 전체 정지 해제만으로 수집·자동 검토가 재개되지 않는다. 소유자의 수집 재활성화가 필요하다.
- API에는 제공자/모델/호출·도구 횟수만 보이며, 내부 대화와 원문 발췌는 job.agentJournal에 보관한다. 암호화 전체 백업에 함께 포함된다. 새 디렉터리 복원은 전체 정지·AI off·수집 off를 적용하고 미완료 예약은 unknown으로 복구한다.
- 오래된 백업으로 되돌리면 백업 후 사용량은 복원할 수 없다. 저장소 자동 복구 시 AI를 끄며, 운영자는 제공자 기록을 대조한 후 다시 활성화해야 한다. 기존 코어는 새 agent 작업을 이해하지 못하므로 agent 작업 생성 후의 운영 데이터를 오래된 코어로 그대로 다운그레이드하지 않는다.

# 기본 요청과 AI 작성 연결 보완 — 2026-09-11

주 제공자(`YENO_AGENT_*`)가 연결되고 AI 모듈이 켜졌으면, 정해진 명령에 해당하지 않는 일반 문장을 같은 영속 agent 작업으로 처리한다. 웹의 `AI 작성`도 레거시 초안 인증이 없는 경우 주 제공자의 호출 예산·중단·기록 경로를 사용한다. 기존 기억·문서·프로젝트 명령은 계속 먼저 처리한다. 별도 코드 실행·배포·발송 권한을 추가하지 않는다.

주 제공자가 없으면 자유 요청을 완료 처리하거나 문서 복사로 대체하지 않는다. 모델 미연결 안내를 반환하며, AI 모듈 비활성·전체 멈춤도 유지한다. 실제 모델 연결과 운영 반영은 `STATUS.md`의 최신 증거를 따른다. 모의 NVIDIA 응답으로 두 진입점의 실제 결과 파일·중복 방지·호출 수·중단을 검사했고 전체 검사164/164를 통과했다.
