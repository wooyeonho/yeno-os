# BLACKHOLE 상태 등록부 설계 초안 — 2026-09-30

상태: **설계만 완료, 런타임 구현 전**. 목표 헌장 P1에 따라 소유자 승인 전에는 저장소·백업 스키마를 추가하지 않는다. 이 문서는 `docs/STATUS.json`과 다르다. STATUS는 실행 기록에서 생성하는 공개 가능한 진행 현황이고, 이 등록부는 미래의 런타임 상태 출처를 명확히 할 설계다.

## 필요한 이유와 범위

현재 상태는 `store.mjs`의 여러 최상위 키에 저장된다. 등록부가 생긴다면 기존 상태를 복사하거나 대체하지 않고 **각 사실의 정본 위치와 신뢰 등급을 가리키는 읽기용 색인**이어야 한다. 새 타이머, 자동 실행 권한, 외부 호출을 만들지 않는다. 소유자·기기·모델·외부 출처 주장을 하나의 `ready` 플래그로 뭉치지 않는다.

초기 항목은 `id`, `kind`, `sourcePath`, `sourceRecordId`, `observedAt`, `evidenceClass`(`local|synthetic|external|unknown`), `verification`(`verified|unverified|blocked`), `artifactSha256|null`만 제안한다. `sourcePath`는 알려진 저장 키의 식별자이며 임의 파일 경로나 URL은 허용하지 않는다. 이 등록부의 `verified`는 링크·해시 무결성만 뜻하고 모델 답의 정확성이나 외부 성과를 뜻하지 않는다. 자격증명·원문 개인 데이터는 항목에 넣지 않는다.

## 구현 전 결정과 시험 관문

1. 소유자가 등록부 범위와 새 최상위 저장 키 허용 여부를 결정한다. 기본은 **비활성·미구현**이다.
2. 허용되면 기존 저장 상태와 암호화 백업의 복원, 손상 필드 거부, 키 없는 옛 상태 기본값을 구현보다 먼저 시험한다. 기존 `store.mjs`/`backup.mjs` 허용 목록은 필요한 키만 늘린다.
3. 색인은 정본 작업·산출물·판정을 다시 읽어 생성하고, 원본이 사라지거나 해시가 달라지면 즉시 `unverified`로 강등한다. 색인 자체는 실행 허가를 제공하지 않는다(`authorizesDispatch:false`).
4. 격리 코어에서 생성→재시작→백업 복원→원본 변조→강등을 확인한다. 실제 출처는 합성 fixture와 따로 보고한다.

실행 코드 연결, 활성화, 동결 세 파일 수정, Vault 변경은 이 설계에 포함되지 않는다.
