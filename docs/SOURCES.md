# 2026-09-10 추가: 공개 오픈소스·스킬 원문 접수

[ECOSYSTEM_INTAKE](ECOSYSTEM_INTAKE.md)의 별도 상주 수집기가 검색·커밋 고정·문서 바이트/해시 검사를 수행한다. 이 문서의 수동 자료 접수 API와 구분한다. 자동 접수한 원문은 partial/pending이며 설치나 채택이 아니다. 기존 검토를 덮어쓰지 않는다. 실제 가동 상태는 [STATUS](STATUS.md) 최상단을 따른다.

# 개선 자료 접수와 검토

0.2.2는 출처 URL, 읽기 상태, 프로젝트 연결과 적용 판단을 코어에 보존한다. 링크 접수 자체가 원문 조회·학습·개발·배포를 뜻하지 않는다. 이 기능은 외부 사이트를 가져오거나 공급자 API를 호출하지 않는다.

## 사용

웹 조종석의 **자료**에서 공개 HTTPS 링크를 등록하고 확인한 내용, 적용 방법, 권리·개인정보·이용조건의 남은 쟁점을 기록한다. 같은 정규 URL은 중복 등록하지 않는다. 원래 URL은 보존하며 수정할 수 없다. 추적 매개변수는 정규 URL에서 제거하지만 `img_index`처럼 내용 위치를 나타내는 값은 유지한다.

내용 확인 상태는 `unread`(미확인), `partial`(일부 확인), `read`(내용 확인), `unavailable`(접근 불가)다. 적용 판단은 `pending`(검토 대기), `candidate`(개선 후보), `deferred`(보류), `rejected`(미채택)다. 두 상태는 독립적이지만 개선 후보에는 `read`와 비어 있지 않은 요약·적용 방법·쟁점 기록이 필요하다. 이 기록은 실제 구현·검사·배포의 증거를 대신하지 않는다.

기존 Android APK의 명령 창에서도 아래 명령이 문서 작업과 결과를 만든다. 새 네이티브 자료 탭을 빌드한 것은 아니다.

```text
자료 목록
자료 목록 2
자료 목록: God Eye
자료 브리핑: God Eye
자료 브리핑: 자료ID
개선 후보: 자료ID
```

목록은 한 페이지 50개를 표시하며 다음/이전 페이지 명령을 제공합니다. `자료 목록 2: 검색어`로 검색 결과의 다음 페이지도 확인합니다. 이름·주소·저장된 요약·원본 자료명으로 검색하며 이름이 여러 자료와 일치하면 ID를 요구합니다. 원본 자료명은 과거 기록의 검색용 이름이며 실제 기능 검증이 아닙니다. 특정 자료는 브리핑에서 전체 검토 내용을 확인한다. 개선 후보 명령은 이미 검토된 후보의 준비서를 만들며 코딩 작업자를 실행하지 않는다.

## API 1 계약

기존 `/api`와 기기 인증용 `/api/v1` 모두 제공한다. 등록·수정·가져오기는 지속 `requestId`를 요구한다. 동일 요청 재전송은 같은 접수 결과를 반환한다. 기기 폐기는 접수 기록 재사용보다 먼저 검사한다.

| 경로 | 동작 |
| --- | --- |
| `GET /api/v1/sources` | `{sources}` 조회 |
| `POST /api/v1/sources` | 자료 생성, 201 `{source}` |
| `POST /api/v1/sources/:id/update` | 현재 `revision`과 검토 필드로 수정; 충돌 시 409와 현재 자료 |
| `POST /api/v1/sources/import` | 1–100개 전체 검증 후 한 번에 등록; 201 `{sources,createdCount,reusedCount}` |

자료 입력 필드는 `url`, `title`, `projectId`, `readingStatus`, `decision`, `summary`, `application`, `riskNotes`다. 제목 최대 160자, URL 2048자, 요약·적용 방법 각각 8000자, 쟁점 4000자다. 프로젝트는 실제 등록 ID 또는 `null`이다. 가져오기 파일은 배열 또는 `{sources:[...]}`이며 웹 제한 240 KiB, 서버 전체 요청 제한 256 KiB다.

가져오기 전체에 중복 정규 URL이나 유효하지 않은 행이 있으면 아무 행도 추가하지 않는다. 기존 정규 URL과 모든 입력 값이 같은 행은 재사용하며 다른 값이면 409로 전체를 중단한다. 기존 자료를 조용히 덮어쓰지 않는다.

웹은 전송이 끊기거나 인증이 만료되어도 대기 요청 ID를 보존한다. 내용 수정과 재전송을 구분하고, 버전 충돌은 최신 자료를 확인한 뒤 새 요청으로 처리한다.

## 보존과 범위

기존 상태에는 `sources: []`만 추가한다. 이미 존재하는 자료 저장소가 손상되면 빈 배열로 바꾸지 않고 검증된 백업 복원 또는 오류 종료 경로를 따른다. 프로젝트·작업·기억·기기·기존 접수 기록을 보존한다. 여전히 단일 프로세스 JSON 저장소다.

공개 DNS 이름의 HTTPS 링크만 받으며 자격 증명·비밀값으로 보이는 매개변수, IP 주소, 로컬 호스트와 사용자 지정 포트는 거부한다. URL 형식 검사는 DNS 해석이나 원문 신뢰성·권리 검증이 아니다. 향후 실제 수집기는 별도의 네트워크 범위·리다이렉트·콘텐츠 크기 제한을 구현해야 한다.

전체 멈춤 중에도 자료 정보는 편집할 수 있지만 새 문서 작업 실행은 기존 전체 멈춤 규칙을 따른다. 자동 검색, 모델 검토, 코딩, 배포와 독립 백업은 별도의 실제 연결·검사 증거가 있어야 활성 기능으로 표시한다.
