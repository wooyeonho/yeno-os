# CODEX 지시서 — 실측 전 RAM 3GiB 확보 절차 (2026-09-27)

작성: Claude(Cowork). 이 세션 내내 실측 시 여유 RAM이 0.19~0.71GiB였고 3GiB 게이트를 넘긴 적이 0번이다. 병목은 코드가 아니라 PC 메모리 확보 절차 부재다. 이 지시서는 코드가 아니라 **실행 전 확보 절차**다.

## 0. 유지 (완화 금지)
- 소유자 승인 게이트, RAM<3GiB 차단 게이트 자체는 그대로 둔다 — 게이트를 낮추거나 우회하지 않는다.
- 소유자의 다른 작업(문서, 브라우저 탭 등)을 소유자 동의 없이 강제 종료하지 않는다. 자동으로 닫아도 되는 것은 "이 실측 목적으로 이 세션이 띄운 것"과 "중복 실행된 Ollama 프로세스"뿐이다.

## 1. 먼저 안전하게 되찾을 수 있는 메모리부터
1. `ollama ps`로 이미 떠 있는 모델을 전부 확인하고, 이번 실측에 안 쓰는 모델은 `ollama stop <model>`로 내린다.
2. Ollama 서비스 자체를 한 번 재시작한다(`Restart-Service`나 트레이 종료 후 재시작) — 반복 실측으로 상주 프로세스가 메모리를 누적했을 가능성.
3. `Get-Process | Sort-Object WorkingSet -Descending | Select-Object -First 15 Name,Id,@{N='RSS_MB';E={[math]::Round($_.WorkingSet/1MB)}}` 결과를 실행 기록에 남긴다. 상위 항목 중 이번 실측과 무관한 무거운 프로세스(브라우저, IDE, Electron 앱 등)가 있으면 **소유자에게 종료해도 되는지 물어보고** 종료한다. 소유자 승인 없이 임의로 끄지 않는다.
4. 위 조치 후 여유 RAM을 다시 측정해 게이트 리포트에 "확보 전/확보 후" 두 값을 모두 남긴다.

## 2. 그래도 3GiB가 안 되면
1. 소유자에게 직접 알린다: 어떤 프로세스가 몇 MB를 쓰고 있는지 표로 제시하고, 종료 여부를 소유자가 정하게 한다. 임의 판단으로 대신 끄지 않는다.
2. 물리 메모리 자체가 부족한 것이라면(설치 RAM 용량 한계) 이는 코드로 해결 불가 — 그 사실을 있는 그대로 기록하고, 더 작은 모델(예: 1.5B급)로 같은 게이트 실측을 한 번 병행 제안한다. 로컬 독립 실행이라는 소유자 조건은 유지하되, "이 PC에서 3B가 상시 가능한지"와 "더 작은 모델로는 되는지"를 분리해서 숫자로 남긴다.

## 3. 검증
1. 확보 전/후 RAM 수치와 `Get-Process` 상위 목록이 실행 기록에 있는가.
2. 소유자 동의 없이 종료된 프로세스가 없는가.
3. 확보 후 실측에서 3GiB 게이트를 실제로 통과했는가 — 통과했다면 이번 세션 첫 번째 성공.
