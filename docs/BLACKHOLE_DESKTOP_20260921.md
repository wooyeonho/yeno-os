# BLACKHOLE 개인 Windows 실행판

이 조각은 PR #50 `7e058c5048409b2c00ab3e8b84318017eb809648` 위에 쌓는 **실행 패키지**다. 기존 `server.mjs`, 저장소, 작업 실행기, 모델 실행기, 웹 운영실을 그대로 사용한다. PR 병합이나 운영 배포가 아니다.

## 사용 순서

1. 이 PR의 **BLACKHOLE Windows desktop package** 성공 실행에서 `BLACKHOLE-Windows-x64-<commit>` artifact를 받는다. 바깥 artifact ZIP 안의 `BLACKHOLE-Windows-x64-<commit>.zip`도 새 폴더에 모두 푼다.
2. `BLACKHOLE.exe`를 연다. Windows 10/11 x64와 .NET Framework 4.x가 필요하다. Node와 잠금 파일 기준 의존성이 포함되어 Git, npm, Rust, 개발 도구 설치는 필요 없다. 실행 파일은 아직 서명되지 않았다. 조직 정책이 실행을 차단하면 우회하지 않는다.
3. **기존 코어 열기**는 입력한 HTTPS 운영실로 이동한다. **이 PC에서 새로 시작**은 별도의 빈 개인 저장소를 만들며, 기존 클라우드 기억을 가져오지 않는다. 새 저장소 확인과 16자 이상 연결 키를 입력한 뒤 **운영실 열기**를 누른다.

로컬 시작 후 바로 가능한 작업 예:

- `기억해: 내 프로젝트에서 가장 중요한 목표는 ...`
- `찾아줘: 프로젝트`
- `문서 만들어: 오늘 처리할 일 ...`
- `진단해`

결과는 기존 작업/결과 화면에서 연다. 목표·Seven Drives·Shadow Army·JEV 관찰·소설·연구·커비 등 기존 화면과 실행 조건을 유지한다. 관련 화면이 있다는 사실은 모든 프로젝트가 실행되거나 완성됐다는 뜻이 아니다.

시작 화면의 **기존 프로젝트·키워드 목록 가져오기**는 기존 canonical 50개 기획과 추가 키워드를 기존 source intake에 등록한다. 같은 버튼을 다시 눌러도 기존 기능의 중복 방지를 이용한다. 원문 열람·실행·검증·프로젝트 완성으로 승격하지 않는다.

## AI 연결

시작 화면에서 OpenAI/GPT, Anthropic/Claude, Google/Gemini, xAI/Grok, Moonshot/Kimi, NVIDIA 중 사용할 공급자의 **API 키와 실제 모델 API ID**를 넣는다. ChatGPT 같은 채팅 구독 자체가 API 키는 아니다. 모델 이름·무료 제공·실제 인증 성공을 추정하지 않는다.

키는 이 PC Windows 사용자 범위 DPAPI로 암호화한다. 저장만으로 AI를 켜거나 호출하지 않는다. 키 변경 시에도 기존 AI 설정을 끄며, 진행 중인 작업이 있으면 먼저 일시정지를 요구한다. 운영실 설정에서 사용자가 AI를 켠 뒤 직접 맡긴 명령은 기존 provider/router, 작업 원장, 미확인 호출 보류 규칙으로 실행한다. 하루 1~20회 한도는 **호출 횟수**이고 금액 보장이 아니다. 모든 AI가 없어도 로컬 기억·문서·상태·중단 기능은 동작한다.

## 저장과 종료

- 개인 기록: `%LOCALAPPDATA%\BLACKHOLE\desktop-v1\data`
- 암호화 설정: 같은 폴더의 `desktop.dpapi`
- 로컬 코어: `http://127.0.0.1:8791`
- 시작 화면: 로컬 포트 8792, 실행마다 새 접근 nonce. nonce는 URL fragment에서 읽고 즉시 지우며 브라우저 저장소에 보관하지 않는다.
- 창을 닫아도 트레이 프로세스가 실행 중이면 코어는 계속 동작한다. 트레이의 **종료 (작업 상태 보존)**는 기존 shutdown을 통해 작업을 보존한다. 재시작 시 미완료 작업은 기존 복구 규칙에 따라 일시정지되고, 미확인 외부 호출은 자동 재전송하지 않는다.
- 동일 포트를 쓰는 두 번째 인스턴스는 실패한다. 기존 데이터 잠금과 상태를 강제로 해제하지 않는다.

운영실 로그인은 기존 HttpOnly 기기 쿠키를 사용한다. 키를 URL/로그/브라우저 저장소에 넣지 않는다. Windows 관리자 또는 이미 침해된 현재 사용자 계정까지 막는다는 주장은 하지 않는다. 기록 전체의 암호화를 주장하지 않으며, 민감 설정은 DPAPI, 데이터 파일은 현재 사용자 전용 ACL로 보호한다.

## 검증 경계

`runtime/test/desktop.test.mjs`: 실제 임시 HTTP 코어, 실제 파일·기억·작업·결과 해시·재시작. 암호화 어댑터는 합성 AES-GCM이며 Windows DPAPI 증거가 아니다.

`runtime/test/desktop-provider-config.test.mjs`: 기존6공급자 설정·비밀값 없는 상태·실행 원장·호출 상한·미확인 재전송 방지. 전송은 합성이며 실제 모델 품질/계정 연결 증거가 아니다.

`runtime/test/desktop-ui.test.mjs`: 실제 setup HTTP 경로와 배포할 HTML/JS를 DOM 환경에서 연결한다. 물리 폰이나 Windows 브라우저 영상 검증이 아니다.

`desktop-windows.yml`: Windows에서 실제 EXE 컴파일 → ZIP 생성 → 다른 폴더 압축 해제 → 내부 모든 해시·Node 서명·라이선스 → 컴파일된 EXE의 DPAPI/ACL → 실제 코어/native API 명령·결과·재시작 검사. 검사 통과 후에만 실행 ZIP artifact를 업로드한다. 워크플로 파일의 존재와 실행 성공은 구분하며 PR/Issue 보고에 실제 run/head/hash를 기록한다.

## 현재 남는 한계

- 새 로컬 코어는 PR #50 상주 작업, 기존 0.2.3, Koyeb, Vercel, Supabase, Obsidian과 자동 병합/이전되지 않는다.
- 이 데스크톱 실행판은 자동 로그인 시작이나 원격 PC 조작을 등록하지 않는다. PC 종료·절전 시 로컬 코어는 사용할 수 없다.
- 폰과 같은 상태를 쓰려면 동일한 코어를 선택하고 검증된 HTTPS 경로를 연결해야 한다. 이 패키지는 Tailscale 계정이나 공개 경로를 자동 만들지 않는다. 기존 HTTPS 코어 열기 경로는 기존 폰 데이터와 연결을 보존한다. 새 로컬 코어의 실제 폰 연결은 별도 수락시험이 남는다.
- Grok API 설정은 Grok Bot 제품 연결이 아니다. JEV는 기존 Shadow Mode이며 dispatch 권한을 추가하지 않는다.
- 모든 프로젝트의 무인 완성, 세계1위, 자동 수익, 의미 품질, 법률/보안 완전성은 증명하지 않았다.
- 실제 모델 인증은 사용자 API 키로 허용된 요청이 성공한 뒤에만 확인된다. 이 개발/CI 실행은 실제 모델 키를 사용하지 않는다.

## 되돌리기

트레이에서 종료한 뒤 이전에 쓰던 서버/앱을 계속 사용한다. 이 패키지의 새 데이터 폴더와 압축 해제 폴더는 그대로 보존한다. 자동 업데이트·삭제·마이그레이션·기존 키 회전·생산 환경 변경은 없다.
