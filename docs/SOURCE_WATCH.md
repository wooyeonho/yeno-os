# 상주 코어의 공식 자료 자동 확인

2026-09-10 구현. 실제 배포·첫 실행 결과는 STATUS / LIVE_ACCEPTANCE의 최신 기록을 따른다.

## 하는 일

ChatGPT 대화나 예약 조사에 의존하지 않고 실행 중인 YENO 코어가 24시간마다 공식 GitHub 릴리스 목록을 확인한다. 공개 GET만 사용하며 모델 호출, 키, 새 계정이 필요 없다. 기존 서버의 가동·네트워크 조건은 필요하다.

- 출처: openai/codex, anthropics/claude-code, google-gemini/gemini-cli, tauri-apps/tauri, xai-org/xai-sdk-python.
- 출처별 최신 20개 목록에서 최근 7일의 정식 릴리스만 확인한다. 신규 자료는 출처별 최대 2개, 회당 최대 10개다. 모든 릴리스 수집을 보장하는 검색기가 아니다.
- 제목·주소·게시/확인 시각을 기존 sources에 저장한다. 원문 내용·실행 스크립트는 저장/실행하지 않는다. 정규 URL로 중복을 막으며 기존 검토를 덮어쓰지 않는다.
- 모두 `readingStatus=unread`, `decision=pending`. 발견, 원문 검토, 채택, 구현, 시험, 배포는 별개다.
- 출처당 8초·응답별 2MiB, 고정 HTTPS endpoint, redirect:error, 무인증 요청. 목록이 크기 제한을 넘으면 같은 8초 제한 안에서 `/releases/latest`를 딱 한 번 조회한다(출처별 최대 2회, 한 주기 최대 10회 GET). 바이너리 자산을 내려받거나 크기 제한을 풀지 않는다. 자료 저장소 5,000개부터 추가 수집을 보류한다. 실패는 출처별 제한된 오류 코드로 기록하고 다음 정기 확인까지 기다린다.
- 다음 확인 시각을 네트워크 요청 전에 저장한다. 재시작·중지/시작 반복으로 호출을 폭증시키지 않는다. 재시작 중이던 실행은 interrupted로 표시하고 다음 예약을 유지한다.
- 전체 멈춤은 수집도 끈다. 해제 후에는 명시적인 수집 시작이 필요하다. 암호화 백업 복원 및 검증된 이전 상태로의 복구도 수집을 끈다.

## 기존 APK에서 사용

`자율 점검` → 완료된 문서에서 마지막 실행·신규 접수 수·출처별 실패·다음 시각을 확인한다. `자료 목록`에서 접수된 자료를 볼 수 있다. 문서는 생성 시점 상태다.

`자료 자동수집 시작`, `자료 자동수집 중지`로 설정한다. 기본값은 꺼짐이며 기존 소유자 지시로 운영 코어에 활성화한 사실은 실제 API 증거로 따로 기록한다. 새 APK 설치는 이 서버 명령 사용의 전제 조건이 아니다.

`POST /api[/v1]/discovery`: `{enabled:boolean,requestId:string}`. 버전 API는 기존 기기 인증을 사용한다. `GET /api[/v1]/state`에 discovery 설정/실행 기록과 scheduledSourceDiscovery capability를 제공한다. 요청 접수 성공만으로 수집 성공을 표시하지 않는다. 중지 API는 요청 원장 용량이 가득 차도 전체 멈춤과 같은 제한된 안전 경로로 동작한다.

## 아직 하지 않는 일

일반 웹 검색, 다른 채팅·개인 SNS 피드 열람, 자료의 AI 해석, 자동 후보 승격, 코드 생성·도구 실행, 시험·병합·배포는 미연결이다. Claude/Gemini/Grok 관련 릴리스 관찰은 해당 모델 실행 연결이 아니다. Perplexity 검색도 API 호출을 연결한 상태가 아니다. 기존 APK 자동 빌드는 개발 소스가 변경된 뒤의 후속 과정이다.

다음 실제 목표는 공급자 인증·비용 한도가 확인된 한 실행 경로에서 `확인한 자료 → 한 변경 제안 → 격리 수정 → 실패/성공 시험 → 비교 가능한 결과`를 완주하는 것이다. 현재 Codex가 개발을 수행하며 이 문서를 개발 작업자 실행 증거로 취급하지 않는다. 운영 기억·키를 생성 코드에 넘기거나 무제한 자동 적용하지 않는다.

## 보존·검사

기존 자료·작업·요청 원장을 보존하며 선택적 discovery 필드만 추가한다. 전체 백업에 포함하고 복원할 때 비활성화한다. 기억/설정 스냅샷 범위에 포함하지 않는다. 이 필드를 모르는 이전 코어로의 다운그레이드는 백업 스키마와 수집 중지 상태를 먼저 확인해야 한다.

Node 검사는 하루 간격·중복/재시작·수집 중 전체 멈춤·HTTP/JSON/용량 오류·저장 실패·외부 URL/미래 자료/초안 차단·기존 API/문서 명령·백업/복원을 검증한다. 가짜 출처 검사를 실제 인터넷 수집 성공으로 표시하지 않는다.

## 확인한 원자료와 제품 판단 (2026-09-10)

- [GitHub 공개 릴리스 API](https://docs.github.com/en/rest/releases/releases#list-releases): 공개 릴리스는 무인증 조회 가능. 이번 수집기의 실제 입력 계약이다. 출처의 저작권·이용조건을 없애는 허가가 아니므로 메타데이터·링크만 접수한다.
- [Grok Bot 공식 설명](https://docs.x.ai/grok-bot/overview): 상주 VM, 기억·파일·브라우저 상태, 모바일/데스크톱 접근, 일정에 따른 루틴을 설명한다. YENO에 적용할 원리는 지속 상태와 실행 루프이며 Grok Bot 자체를 연결/실행한 것은 아니다. 접근 범위와 개인정보 검토가 필요하다.
- [Gemini Google Search grounding](https://ai.google.dev/gemini-api/docs/google-search), [Perplexity Search API](https://docs.perplexity.ai/docs/search/quickstart), [xAI Web Search](https://docs.x.ai/developers/tools/web-search): 외부 자료 조사 경로 후보다. 같은 검색 작업에 여러 모델을 중복 호출하는 설계를 기본으로 하지 않는다. 인증·호출 비용·출처 표시·개인 데이터 전송 조건을 확인한 뒤 가장 작은 실제 호출로 비교한다. 이번에는 유료 호출·모델 채택 없음.
- 사용자 [Grok 관련 X 링크](https://x.com/angeldot_/status/2095849798209286198)는 403으로 본문 확인 불가(`unavailable/pending`). 영상/게시물 내용을 추정하거나 공식 문서와 같은 내용이라고 단정하지 않는다. 여행 자료는 수집 범위에서 제외한다.

유명세·수익·세계 최고·법적 무위험은 검증 결과로 약속할 수 없다. YENO의 품질은 실제 작업 성공, 실패 복구, 통제 가능성, 운영 비용과 사용자의 시간 절감으로 평가한다.
