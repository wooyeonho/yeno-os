# BLACKHOLE 독립 OS 실행 경계 — 2026-09-13

## 결론

BLACKHOLE의 본체는 모델이 아니다. 영속 코어는 모델 제공자나 API 키 없이 기동하고 계속 작동한다. 외부 AI는 **개발 작업 또는 명시적으로 접수·기록된 유한 모델 작업에서만 호출하는 선택형 가속기**다.

환경에 실제 API 키와 과거 `YENO_AGENT_AUTORUN=true`가 남아 있어도 자동 연구, 자료 갱신 뒤 자동 검토, 임의 백그라운드 모델 호출을 시작하지 않는다. 키가 연결됐다는 사실은 수동·명시적 호출을 실행할 준비가 됐다는 뜻일 뿐이다.

이 계약은 “모델 없이 모든 문제를 해결한다”는 주장이 아니다. 모델이 필요한 생성·추론은 해당 작업 경계에서 대기하거나 거절되며, 그 장애가 코어의 인증·저장·큐·결과·복구와 로컬 기능 실행까지 정지시키지 않는다는 뜻이다.

## 실행 경계

| 경계 | 모델 필요 | 현재 예시 |
|---|---:|---|
| `local-core` | 아니오 | 문서·진단·개선 후보, 공개 관측, 로컬 영상·For-Ai 점검, 선언형 기능, QuickJS JavaScript 가져오기·시험·실행·롤백 |
| `model-call` | 예 | 사용자가 접수한 자비스 대화, 일반 에이전트, 연구 답안, 프로젝트 봇, 목표 실행의 모델 단계 |
| `development-model-call` | 예 | JavaScript 기능 생성·수리, 개발 과정의 소스 변경안 작성 |
| `unclassified` | 실행 전 분류 필요 | 새로 추가됐지만 경계를 등록하지 않은 작업 유형 |

새 작업 유형은 자동으로 로컬 작업으로 간주하지 않는다. `runtime/lib/independent-core.mjs`에서 분류되지 않은 작업은 `unclassified`로 표시해 AI 의존성이 코어 내부로 묵시적으로 들어오는 것을 막는다.

## AI 없이 계속 작동하는 본체

- 호문쿨루스: 저장된 지표와 규칙으로 허용된 목표 후보의 우선순위를 계산한다.
- 커비: 이미 검증·활성화한 선언형 기능과 QuickJS JavaScript 기능을 실행한다.
- 자비스 코어: 작업 큐, 요청 원장, 기억, 파일 결과, 상태·오류·복구 정보를 제공한다.
- 인증, 요청 중복 방지, 작업 중단·재개·취소, 전체 멈춤, 결과 해시 검증을 유지한다.
- 상태와 결과를 영속 저장하고 종료·재시작 뒤 복원한다.
- 공개 관측, 내부 문서 변환, 진단, 결과 재사용, For-Ai 점검, 로컬 영상 렌더링을 수행한다.

이미 모델 응답이 정산되어 최종 답안 체크포인트가 저장돼 있다면 새 호출 없이 파일 저장 단계를 마칠 수 있다. 새 모델 응답이 필요한 자동 작업은 시작하거나 재개하지 않는다.

## 코어 불변 조건

- 모델 키가 0개여도 서버가 부팅된다.
- 모델 공급자가 없어도 상태·기억·작업·결과를 저장하고 재시작 뒤 복원한다.
- 모델 장애·호출 한도·AI 끄기는 모델 경계 작업에만 영향을 준다.
- 로컬 작업을 편의상 모델 경로로 우회하지 않는다.
- 전체 멈춤, 인증, 호출 원장, 저장소, 백업·복원은 모델 판단에 의존하지 않는다.
- 자동 운영이 모델 작업을 선택하더라도 영속 기록과 호출 상한을 가진 별도의 유한 작업이어야 한다. 상주 모델 프로세스가 아니다.
- 모델을 끄거나 제거해도 기존 로컬 기능과 결과 파일은 남는다.

## 구현

1. **독립 코어 계약** — `runtime/lib/independent-core.mjs`
   - 기존 작업 유형과 코드 작업 모드를 로컬·모델·개발 경계로 분류한다.
   - 독립 코어 상태 요약을 순수 함수로 제공한다.
   - 호스팅 진입점에서 정적 계약을 검사한다.

2. **공개 작업 상태** — `runtime/lib/job-view.mjs`
   - 작업 응답에 `execution.kind`, `requiresModel`, `trigger`, `reason`을 붙인다.
   - 입력·초안·인증값과 같은 비공개 내용은 기존처럼 제거한다.

3. **운영 브리핑** — `runtime/lib/operations.mjs`
   - 저장 작업을 로컬 코어, 일반 모델 호출, 개발용 모델 호출, 미분류로 집계한다.
   - AI 미설정이 독립 코어 정지를 뜻하지 않음을 명시한다.

4. **호스팅 부팅 계약** — `runtime/service.mjs`
   - 모델 설정을 읽거나 호출하지 않고 독립 코어 계약부터 검사한다.
   - 공급자 설정은 코어 기동 조건에 포함하지 않는다.

5. **무키 실제 회귀 검사** — `runtime/test/independent-core.test.mjs`
   - 모델 관련 환경값과 키가 없는 상태로 실제 HTTP 코어를 시작한다.
   - 영속 문서 작업을 완료한다.
   - 커비 JavaScript 기능을 가져와 QuickJS에서 시험·활성화·실행하고 결과 `42`를 확인한다.
   - 자비스 모델 대화·자동 코딩·일반 에이전트는 경계에서 거절되고 모델 전송 함수가 0회인지 확인한다.
   - 코어를 재시작한 뒤 같은 작업 기록과 결과 파일 `42`를 다시 읽는다.
   - 키와 구형 자동 실행 변수가 있어도 새 백그라운드 모델 작업이 생기지 않는지 별도로 검사한다.

## 명시적 모델 호출

모델 사용은 다음 중 하나의 영속 작업으로 제한한다.

- 사용자가 자비스 대화나 일반 모델 작업을 직접 접수한 경우
- 승인된 목표·연구·프로젝트 작업이 명시된 유한 모델 단계를 실행하는 경우
- 사용자가 코드 생성 또는 실패 코드 수리를 접수한 경우
- 개발 과정에서 별도 도구가 소스 변경안을 작성하는 경우

각 호출은 공급자 설정, 하루·작업별 호출 상한, 요청 ID, 예약·정산·미확인 응답 보존, 전체 멈춤을 따른다. 모델 응답은 코어의 정체성·권한·비용 규칙을 바꾸지 못한다.

## 독립의 범위

이는 **모델 API로부터의 실행 독립성**이다. 공개 관측처럼 외부 자료가 필요한 기능은 인터넷 연결이 필요하고, Koyeb 배포본은 Koyeb 인프라에서 실행된다. 현재 코어는 Windows 자체를 대체하는 커널이나 하드웨어 드라이버가 아니며, 임의 네이티브 바이너리·npm 패키지·저장소 전체를 무인 수정·배포하는 개발 작업자는 별도 범위다.

운영 Koyeb 재배포와 실제 휴대폰 마이크·스피커 검수는 소스 구현·자동 검사와 분리해 증거를 남긴다.
