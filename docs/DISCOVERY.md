# 먼저 발견하고 검토하는 YENO

연호님은 관련 사례와 새 기능을 매번 별도로 명령하지 않아도 확인하고 추가하는 방향을 요청했다.

## 기본 흐름

공유된 링크와 지정한 공개 출처에서 발견 → 실제 내용 확인 → 기존 기능과 비교 → 유용한 후보 기록 → 별도 개발 환경에서 시제품·검사 → 허용된 범위에 따라 적용.

공유된 링크는 이 YENO 대화에서 개선 자료로 접수한다. 모든 다른 대화, 개인 SNS 피드, 저장함을 자동으로 읽을 수 있다고 가정하지 않는다. 공식 문서·원 제작자의 공개 설명·소스 등 확인 가능한 근거를 우선한다.

## 현재 가능한 것과 이후 구현

별도의 ChatGPT 예약 작업은 공개 자료를 확인하고 `YENO_FEATURE_BACKLOG.md`에 후보와 근거를 누적하는 용도다. 활성 여부는 실제 작업 설정으로 확인한다. 이 예약을 만든 것만으로 YENO의 자동 코딩·빌드·설치가 작동한다고 표시하지 않는다.

저장소와 개발 작업자가 연결되면 위임된 YENO 범위에서 후보별 시제품, 코드 수정, 검사를 진행한다. 이미 허용된 가역적인 개발 행동에 매번 다시 허락을 요구하지 않는다. 운영 적용은 해당 작업에 부여된 권한과 복원 가능성을 확인한다. 새 지출·새 권한·외부 공개 등 범위를 넘는 조건은 결과와 함께 올린다.

초기 제품의 핵심 흐름인 앱 연결·실제 명령·결과·재접속 검증을 새 기능 탐색 때문에 미루지 않는다. 발견 목록은 유지하면서 실제 개발 우선순위를 정한다.
