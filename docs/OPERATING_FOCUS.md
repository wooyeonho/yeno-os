# YENO 첫 운영 기준과 확장 실험

기준일: 2026-09-09 UTC. 운영 방향과 검증 목표이며 매출·고객 확보·상주 AI 실행 완료 보고서가 아니다.

## 지금의 집중 과제

연호님이 다른 일을 하는 동안 맡긴 프로젝트의 진행·실패·실제 결과를 폰에서 확인하고, 다음 행동 하나를 결정할 수 있게 한다. 현재 등록된 프로젝트는 20개, 관리 상태 active는 yeno-os 1개다. 나머지 19개의 보류 상태와 데이터는 유지한다. 이 분류가 각 프로젝트의 실제 서버를 정지하거나 실행하는 것은 아니다.

2026-09-09 소유자 화면에서 `코어 응답 확인됨`과 revision 73을 확인했다. 최초 폰 등록·상태 조회가 확인된 것이며, 폰 명령·결과 열기·앱 종료/재실행까지 통과한 증거는 아직 없다.

## 첫 사용자 경험

1. 폰에서 `운영 브리핑` 또는 `운영 현황`을 보낸다.
2. 저장된 작업 상태, 진행 프로젝트, 막힌 연결, 다음 작업을 정리한 실제 결과 파일을 연다.
3. 파일에는 조회 시점이 명시된다. 과거 보고서는 보존하고 새 요청으로 최신 보고서를 만든다. 보고서를 읽었다고 업무가 실행되지는 않는다.
4. 중단된 일은 실제 상태로 표시하고, 전체 멈춤 해제와 개별 작업 재개를 구분한다. 전체 멈춤 중에는 새 브리핑 문서 작업도 만들지 않는다. 앱의 상태 조회는 유지된다.

브리핑은 코어의 저장 기록으로 만든다. 모델 호출·외부 조사·개발 실행·정기 감시를 수행하지 않는다. 작업 본문, 기억 본문, 출처 본문, 인증 값을 복사하지 않는다. 실제 설정·검증·미연결을 구분한다.

## 이후 개발 순서

- 첫 관문: 연호님의 폰 명령→결과 열기→앱 종료→재실행 후 같은 결과 확인. 목표는 실제 명령 10건, 재접속 3회에서 누락·중복 실행 0건이다. 이는 초기 수락 기준이며 모든 장애에 대한 보장이 아니다.
- 두 번째: 격리된 Codex 작업자 1개. 허용한 저장소·파일·시간·비용 상한 안에서 수정→검사→결과 회수만 한다. 요청 ID, 기준/변경 커밋, 실행 명령과 종료 코드, 결과 해시를 보존한다. 결과 제출과 독립 검증은 별도 상태다.
- 이번 환경 점검: Codex/Claude CLI와 Docker는 없고, 설치된 bwrap의 격리 실행도 권한 오류로 실패했다. 격리를 해제해 작업자를 켜지 않았다. 현재 개발은 이 Codex 세션이 수행하며 상주 코어가 스스로 코딩하는 상태가 아니다.
- 작업자 선행 조건: 실제 격리 실행 환경, 제공자 인증 경로, 사용 비용 상한. 기존 채팅 구독을 무인 API 사용권으로 가정하지 않는다. 그 연결 전에는 `developerWorker:false`를 유지한다.
- 제품 수준 관문: 독립 백업에서 빈 환경 복원, 전체 멈춤 전달·실제 종료·안전한 재개, 장시간 사용 확인. Windows 설치본과 PC 제어는 별도 개발·실기기 검증이다.

## 첫 고객 가설과 뉴욕 확장

첫 고객 가설은 본업을 병행하며 여러 작은 웹 프로젝트를 관리하는 Android·Windows 사용자다. 한 가지 제안은 “수정 요청을 맡기면 변경 파일·검사 결과·막힌 이유를 폰에서 확인한다”이다. 뉴욕은 이후 이 가설을 시험할 지역이며, 뉴욕 주민 전체의 수요를 확인한 것은 아니다.

2026-09-09 공식 제품 설명을 확인하면 반복 업무 에이전트와 자연어 앱 제작·검사는 이미 제공되고 있다. 범용 AI라는 이름만으로 선점이나 독점성을 주장할 근거가 없다. [Notion AI](https://www.notion.com/product/ai), [Replit Agent](https://replit.com/products/agent). 공급자 설명을 읽었으며 비교 성능 시험은 하지 않았다.

축적할 자산은 특정 작업의 검증된 절차, 수정 전후 기록, 실패와 복구 사례, 실제 사용자 반복 사용이다. 다른 사람의 비밀 자료를 섞어 학습하는 방식은 사용하지 않는다.

실험 단계는 다음과 같다. 일정과 숫자는 앞으로 확인할 목표이며 달성 실적이 아니다.

| 단계 | 목표 | 확대 조건 |
| --- | --- | --- |
| 연호님 단독 사용 | 초기 7일 동안 위 명령·재접속 수락 기준 확인 | 실제 결과를 다시 찾아 쓸 수 있음 |
| 작업자 연결 | 합성 자료의 작은 수정 10건 | 결과·검사·중단 기록이 남고 8건 이상 추가 설명 없이 완료 |
| 문제 확인 | 같은 불편을 가진 3명에게 합성 자료로 비공개 시연 | 반복되는 문제·기존 해결 방식·절약 시간을 기록 |
| 유료성 확인 | 계정 분리 뒤 사용량 제한을 둔 소규모 시험 | 자발적 반복 사용과 실제 결제 1건 확인 |
| 지역 확장 | 위 증거가 있을 때 뉴욕의 같은 사용자군으로 확대 | 지원 시간이 주 5시간 이하이고 직접 비용을 감당할 수 있음 |

가격은 사용량·원가·반복 사용을 본 뒤 정한다. 자동 결제·외부 연락·홍보 게시·계정 생성은 이번에 수행하지 않는다. 개인 코어의 소유자 키를 시험 사용자에게 나눠주지 않으며, 외부 고객용 계정·데이터·권한 분리가 먼저다.

## 운영 책임과 완료 표시

이 세션의 Codex는 허용된 개발·검사·운영 기록 반영을 진행한다. 상주 코어의 자동 실행 능력은 실제 연결된 것만 표시한다. 기존 일일 기능 조사와 코어 개발 실행은 별도다. 후보 → 구현 → 검사 → 서버 반영 → 폰 실사용 확인을 각각 증거로 구분한다.

오늘의 결과는 운영 브리핑 구현과 실제 결과 회수까지 확인해 기록한다. 다음 결정은 격리된 개발 실행 경로와 비용 상한을 구체화한 뒤 진행한다.
