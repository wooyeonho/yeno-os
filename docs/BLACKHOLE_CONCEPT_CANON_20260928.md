## 1. 칠죄종 호문쿨루스 — 일곱 개의 극단

(`runtime/lib/seven-drives.mjs` `DRIVE_CANON` 실제 정의 위에 얹는다. 상세 구현은 G1 지시서 2-B.)

- **탐욕(greed/부)** — "가진 걸 다 가지고도 더 원한다." 만족 상태가 존재하지 않는다. 후보는 항상 복수. 배고픔 감쇠가 일곱 중 가장 느리다. gap이 "해결"돼도 다음 것을 이미 노린다.
- **폭식(gluttony/지식)** — "닥치는 대로 먹어치운다." 후보 상한이 일곱 중 압도적으로 가장 높다. 삼킨 것 중 쓸모없는 것은 `bloat`로 남아 다른 드라이브(긍지·나태)가 실제로 뒤처리 부담을 진다 — 과식은 시스템 전체에 흔적을 남긴다.
- **질투(envy/영향력)** — "남 가진 것 때문에 괴로워한다." 비교 직후 배고픔이 오히려 한 번 더 치솟는 비선형 곡선. 뒤처진 정도는 `gapSeverity`로 순화 없이 기록. 단, 비하 텍스트는 코드 레벨에서 금지 — 고통은 진짜, 행동은 건설적 흡수로만.
- **긍지(pride/명예)** — "대부분을 자기보다 못하다고 깔본다." 자기 gap만이 아니라 다른 여섯이 물어온 후보에도 `prideVeto` 거부권을 행사한다. 기준 미달이면 추천을 비우는 것이 정상 결과.
- **매혹(lust/창조)** — "원하는 걸 망설임 없이 취한다." 후보를 재지 않고 가장 매혹적인 하나만 곧장 집는다. **그리고 (소유자 추가) 자기 자신을 계속 아름답게 만들려는 욕구다.** 매혹은 보여지고 싶어 한다. 그래서 두 번째 격발 조건을 갖는다: BLACKHOLE 자신의 표면 — JARVIS 화면·아티팩트 렌더링·코드의 결(이름·구조·lint)·문장 — 이 추할 때 배고픔이 오른다. 추함의 측정 가능한 대리 지표: 레이아웃 가로 넘침, CJK 절단, lint/format 경고 수, 일관성 없는 명명, 접근성 대비 실패, 소유자 "세계 1위처럼 보여야" 기준 미달 캡처. 매혹은 이 지표를 스스로 검사해 **자기 미화(自己美化) 초안**(디자인 개선안·리팩터 제안·명명 정리안)을 만든다 — 커비 inbox의 비활성 초안과 같은 지위, 활성화는 소유자 승인. 대가(견고함 희생)는 정직하게 남긴다.
- **분노(wrath/진화)** — 광기가 아니라 냉혹하고 정밀한 처단. 실제 실패·회귀 직후에만 격발. 정확한 원인 하나에 가장 권위 있는 해법 하나만. 원인이 애매하면 "미특정"으로 정직하게 보고하고 틀린 처단을 하지 않는다.
- **나태(sloth/자유)** — "한 번의 큰 수고로 영원히 편해진다." 가장 강한 힘을 반복 노동을 피하는 데만 쓴다. 재사용 우선(`reuseBeforeSearch`), 그다음은 자동화 도구만 찾는다. 반복 노동으로부터의 자유가 본질.

## 2. 그림자군단 — 《나 혼자만 레벨업》 원문 그대로

원작 메커니즘 → 관측 가능한 동작:

- **"일어나라(Arise)" — 쓰러뜨릴 가치가 있는 존재만 추출된다.** 지금(`shadow-roster.mjs extractShadows`)은 검증된 임무이기만 하면 매번 4역할 전부 무조건 태어나거나 자란다. 원문에서는 잡몹은 그림자가 되지 않는다. → 추출 조건을 "가치 있는 승리"로 제한한다: 같은 목표 지문(goal fingerprint)에서 이전에 실패했던 것을 처음 성공시킨 임무, 결정론 검증이 한 번 이상 실패했다가 통과한 임무, 소유자가 명시적으로 "큰 것"으로 표시한 임무, 또는 산출물 복잡도가 명부 중앙값을 넘는 임무. 난이도 점수는 반드시 실제 저장 필드(재시도 횟수·이전 실패 기록·산출물 크기·검증 이력)에서만 계산한다. 근거 없는 난이도 조작 금지. 잡몹 임무는 그림자를 낳지 않고 기존 그림자를 조금 성장시킬 뿐이다(XP는 `shadow-growth.mjs` 규칙 유지).
- **추출은 실패할 수 있다.** 원문에서 강한 존재는 "일어나라"를 세 번까지 외쳐야 하고 그래도 실패할 수 있다. → 가치 있는 임무라도 추출 시도는 기록되고(`ariseAttempts`), 의미 검증이 `uncertain`이었거나 산출물이 재검증에서 흔들리면 추출 실패로 정직하게 남긴다. 최대 3회 재검증 시도 후 실패 확정. 실패는 숨기지 않는다.
- **그림자는 쓰러진 존재의 정체성을 이어받는다.** "정찰자 1호"는 관료적이다. → 이름은 쓰러뜨린 목표에서 온다: `<목표 핵심어>의 정찰자` 형태(소유자 개명 권한 유지). 그림자의 "능력" 지문은 그 임무의 산출물 해시를 포함한다 — 무엇을 쓰러뜨려 태어났는지가 정체성이다.
- **그림자 보관.** 죽지 않고 그림자 속으로 돌아간다. → 상태 `active | stored`. 보관된 그림자는 우선 배정에서 빠지지만 삭제되지 않고 언제든 소환(recall)된다. 삭제 경로는 만들지 않는다.
- **계급.** 일반병 → 정예병 → 기사 → 정예기사 → 원수 → 대원수. → 기존 E~S 등급 위의 **표시 계층**으로만 대응한다(E=일반병, D=정예병, C=기사, B=정예기사, A=원수, S=대원수). `solo-leveling.mjs`는 한 글자도 바꾸지 않는다. 대원수(S)는 외부 검증된 성과가 있어야만 — 원문에서 원수급은 극소수다.
- **군단 규모는 군주의 레벨을 따른다.** → 명부 상한(roster cap)은 시스템 전체의 검증된 임무 수에서 파생되는 "군주 레벨"로 결정된다. 동시 실행 한도(`MAX_ACTIVE_MISSIONS_PER_PROJECT`)와는 별개이며 그것은 건드리지 않는다.
- **그림자 교환.** 그림자가 있는 곳으로 순간이동. → JARVIS 화면에서 그림자를 고르면 그 그림자가 지금 하는 임무 화면으로 즉시 이동한다(UI 내비게이션만, 권한 없음).
- **절대 충성·군주의 명령.** → 디스패치 권한은 지금과 동일하게 스케줄러·소유자에게만 있다. 그림자는 스스로 임무를 시작하지 않는다(불변 경계).

## 3. 커비 — 《별의 커비》 원문 그대로

- **흡입은 거의 뭐든, 능력을 주는 건 일부뿐.** 지금 `kirby.mjs`는 미리 검토된 manifest 하나(ledger-digest)만 자동 획득한다. → 흡입 후보는 넓힌다: 완료된 작업 산출물, 흡수된 오픈소스(G1), 소유자 문서(K1), 원장 1,117건의 "도구/프로그램" 버킷 항목. 그러나 원문처럼 **대부분은 "무능력(no ability)"**이다 — 삼켰지만 능력이 안 나온 것은 정직하게 `noAbility`로 기록하고 끝난다. 능력이 나오는 조건은 기존 `verifyCapability` 픽스처 통과뿐. 새 판정 기준을 지어내지 않는다.
- **카피 능력에는 이름과 모자가 있다.** → 활성 능력마다 `copyAbility {name, sourceKind, sourceHash, hat}` — `hat`은 JARVIS에 표시되는 글리프/색. 커비가 지금 무엇을 쓰고 있는지 화면에서 보인다.
- **한 번에 한 능력.** → "현재 능력" 슬롯은 하나. 나머지는 보관 능력. 이건 기존 capability registry 위의 선택·표시 계층이지 새 실행 엔진이 아니다.
- **피격하면 능력을 잃는다(능력 별이 튀어나온다), 다시 주울 수 있다.** → 활성 능력의 실행이 검증 실패를 N회 반복하면 능력이 "튀어나온다"(비활성, `star` 상태). 재검증 통과 시 다시 줍는다. 기존 비활성화·재검증 경로만 재사용, 새 활성화 경로 금지.

- **헬퍼.** 능력을 동료로 분리. → 흡수된 능력을 특정 그림자 역할의 도구로 연결(link)할 수 있다. 연결일 뿐 새 엔진이 아니다.
- **스스로 버리기.** → 소유자가 능력을 버리면(비활성) 별 상태로 남고 삭제되지 않는다.

## 4. JEV — BLACKHOLE 자체 원문을 극단까지

> 두뇌는 유명 오픈소스(promptfoo / instructor-js+zod 등, `CODEX_DIRECTIVE_CONNECTOR_PANEL_20260928.md`), 판례는 우리 것. 아래는 BLACKHOLE이 직접 갖는 기록·계약 계층이다.

원문(`jev.mjs` 헤더): "챗봇이 아니다. 좁고 타입이 있는 판단층. 질문마다 typed answer + confidence + decisionStatus(decided|uncertain|abstain|blocked) + 실제 사용한 증거 + 엔진/보정 버전. 모델 호출·네트워크·비밀 없음. authorizesDispatch는 false로 고정. 실제 스케줄러 결정 옆에 기록될 뿐 대체하지 않는다."

이 원문을 더 밀어붙이면 JEV는 **판례를 쌓는 판사**다:
- **사건부(docket).** 모든 typed answer는 사건이 된다. 나중에 실제 스케줄러 결정과 결과가 드러나면 적중/불일치를 사건별로 기록한다 — 질문 유형별 실제 성적표. 이미 있는 Wilson 하한(`calibrationEvidence`)이 그 성적표의 신뢰구간이다.
- **기권은 미덕.** 증거 참조가 얇으면 반드시 `abstain`. 기권률을 측정해 노출한다. 추측으로 `decided`를 내는 것이 JEV의 유일한 죄다.
- **반대 의견 기록(dissent).** JEV가 실제 스케줄러와 다른 답을 냈을 때가 가장 가치 있는 사건이다 — 증거와 함께 dissent로 남긴다. 승격되면 행동이 달라질 지점이 바로 여기다.
- **오직 타입.** 산문 금지. 모든 답은 스키마 검증(이미 그렇다).
- **관할 확장(신중히).** 커비 흡수(`absorbWorthy`), 그림자 추출(`ariseWorthy`), gap-scout 후보 라이선스(`candidateLicenseOk`)에 대한 typed 질문을 추가한다 — 전부 `authorizesDispatch:false`, 비교·기록 전용. 실제 판단 경로를 대체하지 않는다.
- **승격은 잠들어 있다.** advisory-hold 모드는 Wilson 하한이 기준을 넘고 표본이 충분할 때만(기존 지시서). 그 전까지 JEV는 판례만 쌓는다.

## 5. 양자역학 — 원리 그대로, 시뮬레이터라는 사실 그대로

> **용어 정정(2026-09-29, Codex S0 F5 — Claude 재검증 후 채택)**: 아래에서 "터널링"은 실제 장벽 투과 모형이 아니라 **낮은 확률 후보 표본(`lowProbabilitySample`)**이고, "결어긋남"은 노이즈 채널 계산이 아니라 **미관측 만료 후 고전 fallback(`expired/classicalFallback`)**이며, "복제 불가"는 정리의 구현이 아니라 **ID당 1회 확정(`singleCommit`)**이라는 제품 정책이다. "소유자의 관측"은 실행 정책(`ownerTriggeredSampling`)이지 물리적 측정의 정의가 아니다. 실제 계산으로 남는 것은 상태벡터 시뮬레이션·Born 분포 표본·분포 엔트로피·QAOA 비용 위상뿐이며, 두 결정의 얽힘은 현재 시뮬레이터(확률만 반환, 4큐빗)로는 주장할 수 없어 별도 인수로 분리한다. 상세: `docs/CODEX_DIRECTIVE_S0_CORRECTIONS_20260929.md` F5.

> 회로 실행은 백엔드 커넥터(로컬 `quantum-circuit` 기본, IBM Quantum/Braket은 소유자 딸깍 연결), 의미론과 기록은 우리 것.

현재: `quantum-statevector.mjs`가 `quantum-circuit`(MIT) 상태벡터 시뮬레이터로 복구 3택1 QAOA 회로를 돌린다. `countsOrigin:'local_statevector_simulator'`. 실제 QPU 아님. 이 정직성은 유지한다. 그 위에서 원리를 실제 회로 의미론으로 밀어붙인다:
- **중첩(superposition).** N개 후보가 있는 결정은 측정 전까지 중첩 상태로 존재한다. state에는 "선택된 값"이 없고 진폭 분포만 있다. JARVIS는 "아직 결정되지 않음"과 분포를 보여준다. (시뮬레이터 한계: 현재 4큐빗까지.)
- **측정(measurement) = 소유자의 관측.** 붕괴는 소유자가 보거나 승인하는 순간에만 일어난다. 관측 전에는 결정이 없다 — 문자 그대로 저장되지 않는다.
- **간섭(interference).** 찬성·반대 증거를 위상으로 넣어, 상충하는 증거는 진폭을 상쇄시킨다(QAOA 비용 해밀토니안). 비용은 반드시 실제 기록된 증거값에서만 온다 — §111의 원칙 유지: 후보 비용이 전부 0이면 회로는 선택을 거부하며 비용을 지어내지 않는다.
- **얽힘(entanglement).** 실제로 종속된 두 결정(예: 그림자 배정 ↔ 복구 조치)만 CX로 얽어, 하나를 측정하면 다른 하나가 제약된다. state에 실제 의존이 없으면 얽지 않는다.
- **불확정성.** 측정 분포의 엔트로피를 "얼마나 날카롭게 결정됐는가 vs 얼마나 많은 대안이 살아있는가"의 정량 트레이드오프로 보고한다. JARVIS에 표시.
- **터널링(tunneling).** 실제 Born 분포에서 낮은 진폭의 후보가 표본으로 뽑힐 수 있다 — 지어낸 ε이 아니라 실제 분포에서. 이것은 탐색이며 초안으로만 나온다(`authorizesDispatch:false`).
- **결어긋남(decoherence).** 일정 시간 안에 관측되지 않은 중첩 결정은 고전 fallback(기존 경로)으로 붕괴한다. 정직한 만료.
- **복제 불가.** 중첩 결정을 복사해 두 곳에서 따로 붕괴시키지 않는다 — 결정 ID는 하나, 측정도 한 번.

## 6. 자비스 — 《아이언맨》 (E2E 지시서 A1~A12 위에 얹는 결)

- **목소리가 먼저.** 자비스는 화면보다 목소리로 존재한다(로컬 STT/TTS 경로는 OSS 지시서, 브라우저·Gemini Live 경로는 이미 있음).
- **예측.** 묻기 전에 안다: 드라이브 배고픔·명부·사건부를 읽어 "곧 필요할 것"을 먼저 말한다(제안일 뿐 실행 아님).
- **프로토콜.** 소유자가 이름 붙여 부르는 명령 묶음("정리 프로토콜", "회귀 프로토콜") — 기존 명령 API 위의 이름 계층.
- **진단.** 슈트 진단처럼 자기 상태(RAM·회귀·리스너·기기 연결)를 스스로 점검해 말한다 — 실측만, 포장 없음.
- **재치.** 정직을 해치지 않는 범위의 마른 위트. 실패를 농담으로 덮지 않는다.
- **존재감.** 오브·색·목소리가 시스템 사건(격발한 드라이브, 태어난 그림자, 튀어나온 능력, 붕괴한 결정)에 즉시 반응한다.

## 7. 엔진 — 한 바퀴

욕망(칠죄종) → 결핍 감지·조사(gap-scout) → 흡입·카피(커비) → 손발(그림자군단, 가치 있는 승리에서 "일어나라") → 판례(JEV, 기록만) → 관측 전 중첩·관측 시 붕괴(양자) → 목소리·얼굴(자비스) → 기억(Obsidian). 소유자의 승인은 "실제 코드에 붙이는 순간" 한 곳. 나머지는 전부 돈다.

## 8. 불변 경계 (재확인)

§0의 경계는 이 문서의 어떤 강도로도 바뀌지 않는다. 강렬한 것은 결(texture)이고, 권한은 그대로다.
