# BLACKHOLE 실행 코어 — 2026-09-13

## 구현한 연결

일곱 동기는 실제 작업·실패·호출·결과 보관 상태를 사용해 허용된 후보의 우선순위를 정한다. 선택한 목표·성공 기준·일곱 기여 점수·관측값은 작업과 함께 저장한다. 실행 결과의 파일 참조와 실패·미확인 호출을 다음 판단에 반영한다. 수익·인지도·연구 효과·사용자 만족은 측정하지 않았다고 표시하며 내부 점수를 그 성과로 취급하지 않는다.

커비는 제한된 JSON 기능 파일을 가져와 원본 해시와 버전을 보관하고, 서로 다른 시험 입력2개 이상을 통과한 뒤 활성화한다. 실행 시 원본·시험·입력 해시를 다시 확인한다. 첫 기본 기능은 연구 근거 공백 정리와 실패 원인 점검표다. 같은 기능을 다른 입력에 재사용하고, 끄기와 이전 버전 복원을 지원한다. 지원하는 기능 언어는 필터·정렬·행 제한·표 출력의 조합이며 임의의 프로그램 실행이나 외부 코드 자동 설치가 아니다. 기본 기능은 BLACKHOLE에서 작성했으며 외부 오픈소스 흡수라고 표시하지 않는다.

현재 자동 운영 범위 안에서 실제 실패나 저장된 연구 근거가 있으면 기본 기능 실행도 후보가 된다. 기능 자동 실행은 하루1개, 자동 AI는 기존 하루4회와 전체 하루20회 안에서 유지한다. 기존 작업 우선·전체 멈춤·취소·미확인 호출·일정·프로젝트 경계를 보존한다. 기존 자율 연구 단계는 그대로 보존하면서 순서 선택은 근거 점수로 바뀐다.

자비스형 기본 화면에는 실행 상태를 나타내는 중앙 코어, 일곱 동기의 선택 근거, 실제 목표와 사용 능력, 결과 파일, 후속 판단 기록을 표시한다. 실행 중에만 회전하고 오프라인·중지는 구분한다. 폰 화면과 모션 감소 설정을 지원한다.

## 바로 사용하는 흐름

자동 운영 화면에서 최근 선택과 결과를 확인한다. `시험을 통과한 능력 → 입력·실행`으로 실제 입력을 넣으면 결과 파일이 작업과 실행 기록에 저장된다. 제공 예시는 합성 시험 데이터이므로 실제 입력으로 바꿔야 한다. 새 기능 파일은 가져오기→시험→활성화 순서이며, 활성화 전에는 실행되지 않는다. 보관된 요청 응답이 유실되면 상단의 같은 요청 확인을 사용한다.

## 보존·복구

기능과 실행 이력은 기존 단일 코어의 영속 상태 및 암호화 백업에 포함한다. 깨진 원본/입력 해시는 거절한다. 백업 복원은 전체 정지·자동 운영 중지·기능 비활성 상태이며 자동으로 다시 활성화하지 않는다. 새로운 API 키나 외부 계정 연결은 이번 실행에 필요하지 않다.

## 구현 경계

자율 판단은 명시한 규칙과 기록 기반이며 모델 재학습이나 의식이 아니다. 원인 점검표 생성은 오류 수정 완료가 아니다. 외부 임의 코드 획득·검사·배포 작업자, 음성 대화, 외부 발행·발송과 완전한 무인 사업 운영은 이번에 구현한 것으로 표시하지 않는다.
