# 원본 프로젝트 복구와 짧은 명령 — 2026-09-10

웹의 프로젝트 기본 목록은 보관된 기록을 제외한다. 검색하거나 “보관한 기록”을 선택해 과거 저장소20개도 확인할 수 있다. 설치된 APK에서 `프로젝트 목록`, `프로젝트 브리핑: C01`을 사용할 수 있다. C01 같은 원본 코드는 정확히 하나의 프로젝트에 대응할 때만 처리하며 모호하면 거부한다. 목록은 원본49개를 모두 포함한다.

`POST /api/projects/import`: `{requestId, projects:[{name,summary,nextAction,repositoryUrl,status}], archive:[{id,revision}]}`. 최대100개와 보관대상100개, 전체256KiB 제한. 전체 사전 검증 후 한 번에 저장하며 같은 이름·모든 필드가 일치하면 재사용한다. 불일치·중복·보관대상 버전 충돌은 전체 거부한다. 보관한 프로젝트의 미완료 봇만 취소하며 다른 작업·완료 결과를 보존한다. 응답이 불확실하면 같은 requestId와 같은 본문으로 조회/재시도한다. 가져오기가 개발·AI 실행을 시작하지 않는다.

아래는 최초 프로젝트 기능 도입 당시 기록이다.

# YENO 프로젝트 관리 — 코어 0.2.1

프로젝트의 코드 위치, 설명, 다음 작업을 상주 코어에 보관하고 브리핑과 작업 준비 문서를 만든다. 폰과 노트북 브라우저에서 같은 목록을 사용한다.

## 사용

웹 조종석의 **프로젝트**에서 프로젝트를 추가하거나 **내용 수정**으로 다음 작업을 바꾼다. **브리핑 만들기**와 **다음 작업 준비**는 조종석의 작업 목록에 문서 작업을 만들며, 완료 후 **결과 열기**로 실제 결과를 확인한다.

기존 Android APK에서도 명령란에 다음을 입력할 수 있다. 새 네이티브 프로젝트 탭을 추가하거나 APK를 다시 빌드한 것은 아니다.

```text
프로젝트 목록
프로젝트 브리핑: yeno-os
프로젝트 작업: yeno-os | 실제 개발 작업자 연결과 완료 조건 준비
```

이름 대신 프로젝트 ID도 사용할 수 있다. 목록 문서는 긴 설명을 요약해 표시하며 전체 프로젝트 정보는 개별 브리핑이나 웹 목록에서 확인한다.

## 범위

- `진행 / 보류 / 보관`은 YENO 안의 관리 상태다. 이를 바꾸는 동작은 Koyeb·Supabase·Vercel 서버를 켜거나 끄지 않는다.
- 저장소 링크를 등록해도 코드·DB·배포가 YENO로 이전되지 않는다.
- 브리핑은 저장한 정보와 요청으로 만드는 문서다. 실제 개발 작업자는 아직 미연결이며, 이 기능은 GitHub를 읽거나 코드를 작성·실행·배포하지 않는다.
- 기존 기억·작업·결과·기기 인증을 보존하며 프로젝트 저장소를 추가한다. 기억/설정 스냅샷 복원은 프로젝트 정보를 되돌리지 않는다.

## API 계약

기존 `/api` 웹 경로와 기기 bearer를 사용하는 `/api/v1` 경로를 함께 지원한다. API 버전은 `1`을 유지한다.

| 요청 | 본문 / 결과 |
| --- | --- |
| `GET /api/v1/projects` | `{projects:[...]}` |
| `POST /api/v1/projects` | `name`, 선택 `repositoryUrl`, `summary`, `nextAction`, `status`, 필수 `requestId`; 성공 `201 {project}` |
| `POST /api/v1/projects/<id>/update` | 변경 필드, 현재 `project.version`인 `revision`, 필수 `requestId`; 성공 `200 {project}` |
| `POST /api/v1/commands` | 위 명령과 `requestId`; 기존 앱이 표시할 수 있는 `201 {kind:"job",job}` |

수정 버전이 오래되면 `409`와 현재 프로젝트를 반환한다. 저장소는 빈 값 또는 `https://github.com/owner/repo`만 받는다. 같은 이름은 정규화 후 중복 등록할 수 없다.

응답이 유실되면 같은 본문·요청 ID로 재시도한다. 웹 화면은 프로젝트 저장 요청을 명령 요청과 따로 보관하며, 시간 초과·5xx·401·403에는 기존 요청을 유지한다. 다시 인증한 뒤 같은 요청으로 접수를 확인한다. 명확한 유효성 오류와 수정 충돌은 최신 내용을 확인해 새 요청으로 해결한다.

## 검증 기록

정확한 전체 검사 수와 실제 배포·재시작·프로젝트 등록 결과는 `STATUS.md`와 `LIVE_ACCEPTANCE.md`에 기록한다. 로컬 API 검사, 실제 HTTPS 검사, Android 실기기 검사를 구분한다.
