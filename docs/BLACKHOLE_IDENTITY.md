# 블랙홀(BLACKHOLE)

소유자가 YENO OS의 새 제품명을 블랙홀로 정했다. 개인 OS 안에서 원래 진행하던 프로젝트를 다시 실행하고, 외부 지식·오픈소스·방법을 검토·응용해 결과와 자산으로 축적한다.

## 공통 기능과 참고 링크의 계보

49개 항목은 사업·연구·작품의 원본 포트폴리오다. 소유자가 보낸 모든 기능·도구·링크의 전체 목록이 아니다. 앞으로 전체 범위를 설명할 때 포트폴리오, 공통 기능, 참고 원자료와 검토 상태를 함께 제시한다.

- 확인: 2026-09-11, 기존 `yeno_os_organized_by_keyword.md`의 2026-08-29 기록을 직접 읽었다. 파일 식별자 `libfile_2c477f14b130819194c78bfe3de3f88a`. 이전 대화 검색과도 대조했다.
- 소유자가 공유한 원 링크: https://www.instagram.com/reel/DcjMGA9vHxU/?igsi=MTkyMWk0dHl2c2s1Nw==
- 기존 기록에 서술된 기능: 3D 지구본, 공개 항공기·선박·위성·재난 정보, 지도 표시, 음성 조작과 화면 요약. 이번에 원 영상·제작자 코드로 재검증한 기능 목록은 아니다.
- 원래 목적: 공개 신호를 출처·시각·신뢰도와 함께 모아 상황을 요약하는 World Layer. 기존 자료에서도 별도 World Sandbox에서 비용·API·출처·정확도를 시험하도록 정리돼 있었다.
- 제품 내 위치: 공통 리서치·상황판 기능. C01 Buzz와 EUREKA, A02 여기에서 활용 가능성을 시험한다. 이 세부 소비처 연결은 이번 운영 제안이며 구현 완료 표시가 아니다. 50번째 독립 프로젝트로 중복 생성하지 않는다.
- 상태: 기존 정리자료 `read`; 원 영상/제작자 원문 `readingStatus=unread`, `decision=pending`. 코어 등록·구현·검사·배포 증거는 이번 조회에서 확인하지 못했다. 이 문서 갱신을 그 증거로 계산하지 않는다.
- 가장 작은 검증: 정확한 제작자/원본 저장소와 라이선스를 확인한 후 공개 재난 데이터 한 종류를 출처·갱신 시각·지연/실패 표시와 함께 격리 화면에 표시한다. 항공/선박/지도 제공자별 API 키·쿼터·요금·재배포 조건은 아직 확인 전이다.
- 권리·개인정보: 코드 라이선스와 데이터/지도 이용조건을 별도로 확인한다. 기존 기록의 사람 검색·얼굴인식·개인추적 제외 원칙을 유지한다. 센서 화면 효과를 실제 열화상·야간투시 관측으로 표시하지 않는다. 여행 내용은 개선 후보에 포함하지 않는다.

과거 대화에 등장한 저장소 주소는 제작자 원문을 확인하기 전까지 확정 출처로 옮기지 않는다. 예전 AI 요약의 ‘사실확인’ 표식만으로 현재 기능 검증을 통과시키지 않는다.

## 채택과 검증

원자료 발견→읽기/권리/개인정보 조건 확인→중복 비교→최소 구현→실제 비교 시험→채택과 복구점 확보 순으로 진행한다. readingStatus와 decision, 코드 구현·검사·배포·실기기 확인을 각각 기록한다. ‘모든 것을 흡수’는 무조건 설치하거나 접근 권한을 늘리라는 뜻으로 해석하지 않는다.

앱에서 실제 명령→결과→닫고 다시 확인하는 흐름을 먼저 완성한다. 비용·시간·사용자 개입을 줄인 결과가 측정된 경우에만 개선으로 기록한다. 세계 최고, 수익·명성 달성, 법적 무위험은 검증된 현황이 아니다.

## 이름 전환의 범위

웹과 네이티브 화면, 앱 제품 표시명에 BLACKHOLE을 적용한다. `kr.yeno.controller`, Stronghold 파일/클라이언트 이름, localStorage 키, 서버 인증, 데이터 디렉터리, `/api`·`/api/v1`와 기존 `YENO OS` 프로토콜 표식은 유지한다. 이름 변경으로 기기를 다시 등록하거나 데이터를 초기화하지 않는다.

새 APK 표시명은 실제 빌드·설치 후 적용된다. 기존 설치 파일과 역사적 산출물은 이전 이름일 수 있다. 표시명 변경만으로 인증 오류, API 공급자 연결이나 무인 개발 실행자가 해결된 것으로 기록하지 않는다.
