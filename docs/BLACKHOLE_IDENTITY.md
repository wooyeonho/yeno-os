# 블랙홀(BLACKHOLE)

소유자가 YENO OS의 새 제품명을 블랙홀로 정했다. 개인 OS 안에서 원래 진행하던 프로젝트를 다시 실행하고, 외부 지식·오픈소스·방법을 검토·응용해 결과와 자산으로 축적한다.

## 확인한 프로젝트 계보

기존 원본 포트폴리오와 손실 방지 매핑을 대조했다. 원본 49개 항목(C00 중앙 관리 포함)을 유지한다.

| 소유자가 부르는 이름 | 기존 항목 | 범위 |
|---|---|---|
| 소설쓰기 | B04 HQ 및 B04-01~13 | 소설·캐릭터·세계관과 기존 13개 IP |
| 인류 난제 | E01~E09, EUREKA | 보존된 연구 트랙, 가설·공식 데이터·재현 검증 |
| for ai | A01 For-Ai | AI 노출 기준 측정→개입→재측정과 증거 축적 |
| 한끼안부 | A03 | 동의 기반 가족 안부 확인 |
| 스마트글래스 SNS / 여기 | A02 Yeogie | 장소 기반 기억·상호작용, 모바일에서 스마트글래스로 확장 |
| 기타 진행 프로젝트 | C01, V01~10, A04~05, B01~03 및 세부 항목 | 원본 레지스트리를 유지하며 개별 목표와 완료 기준으로 실행 |

스마트글래스 연결이 이미 구현됐다는 뜻은 아니다. 관련 아이디어가 A02에 속한다는 원본 매핑이다. GitHub 저장소 이름을 프로젝트 이름으로 대체하거나 위 항목을 중복 생성하지 않는다.

## 채택과 검증

원자료 발견→읽기/권리/개인정보 조건 확인→중복 비교→최소 구현→실제 비교 시험→채택과 복구점 확보 순으로 진행한다. readingStatus와 decision, 코드 구현·검사·배포·실기기 확인을 각각 기록한다. ‘모든 것을 흡수’는 무조건 설치하거나 접근 권한을 늘리라는 뜻으로 해석하지 않는다.

앱에서 실제 명령→결과→닫고 다시 확인하는 흐름을 먼저 완성한다. 비용·시간·사용자 개입을 줄인 결과가 측정된 경우에만 개선으로 기록한다. 세계 최고, 수익·명성 달성, 법적 무위험은 검증된 현황이 아니다.

## 이름 전환의 범위

웹과 네이티브 화면, 앱 제품 표시명에 BLACKHOLE을 적용한다. `kr.yeno.controller`, Stronghold 파일/클라이언트 이름, localStorage 키, 서버 인증, 데이터 디렉터리, `/api`·`/api/v1`와 기존 `YENO OS` 프로토콜 표식은 유지한다. 이름 변경으로 기기를 다시 등록하거나 데이터를 초기화하지 않는다.

새 APK 표시명은 실제 빌드·설치 후 적용된다. 기존 설치 파일과 역사적 산출물은 이전 이름일 수 있다. 표시명 변경만으로 인증 오류, API 공급자 연결이나 무인 개발 실행자가 해결된 것으로 기록하지 않는다.
