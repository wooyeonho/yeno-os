# 폰에서 운영 상태 확인

명령은 `운영 브리핑` 또는 `운영 현황`이다. 기존 APK의 명령·문서 결과 API를 그대로 사용한다.

현재 저장된 작업 상태, 첫 active 프로젝트의 다음 작업, 자료 검토 집계, AI·개발 작업자 연결 표시를 한 문서로 만든다. 현재 기록의 완료 수를 오늘 성과나 수익으로 표시하지 않는다. 이 명령은 실행할 프로젝트를 자동 선택해 시작하거나 외부 개발 작업자를 호출하지 않는다.

## 계약

- 인증된 `POST /api/v1/commands` 또는 기존 `/api/commands`에 위 명령과 `requestId`를 보낸다.
- 기존 `{kind:'job', job:{type:'document', ...}}` 응답과 결과 다운로드 흐름을 사용한다. 서버가 만든 작업에 `operatingReport:true`가 표시된다.
- 보고서는 명령을 접수한 시점의 상태다. 같은 본문·요청 ID 재시도는 같은 작업과 보고서를 반환한다. 최신 상태는 새 요청 ID로 다시 조회한다.
- 생성된 보고서는 다른 문서 작업처럼 중단·재개·취소와 재시작 후 보존 규칙을 따른다. 전체 멈춤이나 문서 모듈 비활성 시 새 보고서 작업을 거절한다.
- 읽기 상태와 채택 판단을 별도로 집계한다. 저장된 후보를 코드 구현·검사·배포 완료로 표시하지 않는다.
- 각 목록은 최대 20개와 전체 수를 표시하고 긴 메타데이터를 제한한다. 작업 입력·기억/자료 본문·기기 인증 필드는 출력하지 않는다. AI 공급자 설정 여부와 실제 호출 성공도 구분한다.

## 검증 범위

순수 모듈 검사와 실제 Node HTTP 통합 검사에서 상태 집계, 원본 보존, 악성 Markdown·긴 입력 경계, native Origin 인증, 실제 파일 해시, 같은 요청의 중복 방지, 서버 재시작 후 결과 보존과 다음 작업 변경 뒤 새 보고서를 확인한다.

실제 운영 서버의 검사 결과는 `LIVE_ACCEPTANCE.md`에 기록한다. 최초 폰 연결은 소유자 캡처로 확인했으며 운영 브리핑의 실제 폰 명령·결과 열기·앱 종료/재실행 확인은 별도다.

구현 후 Node 24.19.0 `npm test` **71/71 통과**, 실패·취소·건너뜀 0, 16.179초. 순수 모듈 4개와 native 명령→결과→재시작→동일 결과/요청 유지 통합 검사 1개를 추가했다. 이 소스 커밋 시점에는 운영 서버 적용·반영 후 HTTPS 검사가 남아 있다.

운영 초점과 고객 실험 가설은 [OPERATING_FOCUS.md](OPERATING_FOCUS.md)를 따른다. 자동 개발 실행자는 별도 연결이다.
