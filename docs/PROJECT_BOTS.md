# 프로젝트 봇 — 2026-09-10

## 실제 구현 범위

한 요청으로 진행(active) 프로젝트마다 첫 산출물 초안 작업을 배정한다. 기존 단일 코어의 저장/실행 큐를 사용하며 코어 복제본이나 외부 프로세스를 추가하지 않는다. 봇은 최대 2개, 전체 작업은 기존 1~3개 범위다. 같은 프로젝트의 실행과 종료 대기 중 호출을 중복 시작하지 않는다. 배정 명령은 최소 동시 실행 수를 2로 설정한다.

- `프로젝트 봇 시작`: primary 모델로 진행 프로젝트 배정. 최대 50개. 미완료 배정 또는 같은 프로젝트 버전/프로필의 기록을 재사용한다. 보류·보관 프로젝트는 시작하지 않는다.
- `모든 프로젝트 봇 시작`: 진행·보류 프로젝트를 함께 배정한다. 보관 항목은 제외한다. 보류 프로젝트의 관리 상태와 실제 외부 서버는 바꾸지 않고, 이번에 위임한 초안 작업만 맡긴다.
- `그록 봇 시작`: 같은 방식으로 별도 xAI 프로필을 지정한다. 이미 맡겨진 작업의 모델은 바꾸지 않는다. **Grok Bot 앱의 봇을 생성하는 명령이 아니다.**
- `봇 운영 재개`: 준비된 일시정지 작업을 재개한다. 프로젝트 변경·모델 변경·응답 미확인 작업은 계속 보류한다.
- `봇 운영 중지`: 봇 작업만 멈춘다. `stoppingJobIds`는 취소 요청을 보냈지만 응답 종료가 아직 확인되지 않은 호출이다. 전체 멈춤은 기존 작업/수집도 멈춘다.
- `봇 현황`: 기존 APK에서 열 수 있는 실제 상태 문서 생성.

`POST /api/bots` body는 `{action:'start',profile:'primary'|'grok',projectIds?:string[],includePaused?:boolean,requestId}` 또는 `{action:'stop'|'resume',requestId}`다. `GET /api/bots`와 `/api/state.bots`로 배정/대기/결과를 확인한다. 기존 기기 인증과 `/api/v1`도 같은 경로를 제공한다.

키·모델·상한이 없으면 작업은 `paused/providerMissing`이며 성공한 봇으로 표시하지 않는다. 키가 준비된 후 시작/재개 명령은 AI 모듈을 켜지만 기존 전체 멈춤을 해제하지 않는다. 기존 `자율 임무:`는 키가 없으면 409로 거부하는 동작을 유지한다. 계정 키를 추가했다고 미확인 호출을 재전송하지 않는다.

## 프로젝트 분리와 비용

작업에 해당 프로젝트의 ID·버전·설명·다음 작업을 고정해 보관한다. `project_read`는 이 사본만, `project_sources`는 해당 프로젝트에 연결된 자료 최대 10개만 읽는다. 다른 프로젝트의 기록이나 개인 기억은 도구 입력에서 제외한다. 공통 공식 자료·공개 오픈소스 발췌는 참고할 수 있다. 프로젝트 문서는 허용 권한을 늘리는 지시가 아니다.

배정과 요청 영수증을 먼저 한 번의 단일 작성자 저장으로 보존한 뒤 스케줄러가 실행한다. 모델 호출도 저장된 예약 이후에 전송한다. 명령 재전송은 같은 requestId를 사용한다. 배치 응답 캐시가 정리되면 410으로 기존 접수 사실을 알리고 `/api/bots`에서 결과를 확인한다. 같은 ID를 새 작업으로 실행하지 않는다.

기본 일일 호출 상한은 기존 YENO_AGENT_DAILY_CALL_LIMIT를 따른다. xAI 프로필도 전체 모델 요청 수를 기준으로 동일 상한 이하에서 실행한다. 하루 상한에 걸리면 `dailyBudget`으로 보류하고 다음 UTC 날짜에 잔여 한도가 있으면 이어간다. 명시적 봇 중지는 이 자동 재개도 끈다. 무응답/중단된 외부 호출은 사용량 unknown으로 남으며 자동 재시도하지 않는다. 호출 횟수는 금액 상한의 대체물이 아니다.

각 봇은 최대 4회 모델 호출, 원문 읽기 최대 2회, 실행 시간 90초, 기존 제한된 응답/체크포인트 크기를 따른다. 결과 파일에는 모델의 초안임과 실제 도구 횟수·출처·미수행 단계를 기록한다. 저장한 제안 코드를 실행하거나 운영 저장소에 적용하지 않는다.

## NVIDIA와 xAI 연결

NVIDIA 설정은 기존 준비값을 보존한다. 이번 계정 접근에서 NVIDIA 로그인 화면까지 확인했으나 인증 입력란 재확인이 시간 초과되어 키 발급/Secret 저장/실제 API 호출은 완료하지 못했다. 로그인·인증을 완료한 뒤 사용 가능한 무료 시험 범위를 확인한다. 실제 키를 채팅, GitHub, 앱 또는 문서에 넣지 않는다.

선택적 xAI 환경 변수:

| 항목 | 의미 |
| --- | --- |
| YENO_GROK_API_KEY | xAI에서 발급해 Koyeb Secret으로 연결한 별도 키 |
| YENO_GROK_MODEL | 계정에서 실제 사용할 수 있는 모델 ID |
| YENO_GROK_DAILY_CALL_LIMIT | 0~20회, 기본 0으로 꺼짐; 기본 프로필의 일일 상한을 초과할 수 없음 |

NVIDIA 키를 xAI로 보내지 않으며 제공자 장애가 자동 유료 전환을 일으키지 않는다. [xAI 공식 시작 안내](https://docs.x.ai/developers/quickstart)와 [현재 Chat Completions 계약](https://docs.x.ai/developers/model-capabilities/legacy/chat-completions)을 2026-09-10 확인했다. 공식 가이드는 API 크레딧 연결을 안내한다. 실제 계정의 크레딧·요금·접근 권한은 미확인이다. 새 결제는 수행하지 않았다.

## 별도 제품 Grok Bot

2026-09-10 확인한 [공식 개요](https://docs.x.ai/grok-bot/overview)는 지속되는 클라우드 작업 환경과 여러 봇의 병렬 수행을 설명한다. [모바일 안내](https://docs.x.ai/grok-bot/mobile)는 Android/iPhone에서 같은 봇을 사용한다고 설명한다. [시작 안내](https://docs.x.ai/grok-bot/get-started)와 [FAQ](https://docs.x.ai/grok-bot/faq)는 대상 계정/플랜과 앱 인증을 요구한다.

이것은 xAI 텍스트 API와 다른 제품이다. 이 작업에서는 설치된 Grok Bot 앱·해당 계정 권한·YENO가 직접 봇을 생성/제어할 공개 API를 확인하지 못했다. Grok Bot 계정과 컴퓨터가 이미 연결되었다고 가정하지 않는다. 봇들이 같은 컴퓨터와 로그인을 공유한다는 공식 설명상, 봇 이름을 여러 개 만든 것만으로 프로젝트의 비밀이 격리되지는 않는다.

연결 후 첫 역할은 프로젝트 하나의 **초안 제작자**로 둔다. 제공할 데이터는 그 프로젝트의 설명·정한 다음 작업·필요한 파일에 한정한다. 반환물은 파일, 출처, 실제 실행한 검사와 로그, 남은 조건이다. 기본적으로 실제 외부 발송·게시·계좌 거래·구매·원본 삭제·운영 배포를 수행하지 않는다. 운영 권한은 검증한 기능별로 따로 연결한다. Grok Bot 제품 인계와 YENO 자동 동기화는 후속 작업이다.

## 보안 수정과 남은 단계

요청 응답 캐시가 정리된 뒤 작업을 재구성하는 경로가 내부 agentJournal을 포함할 수 있는 문제를 수정했다. 초기 응답·상태·과거 캐시·재구성 응답 모두 같은 publicJob 제거 규칙을 사용한다. 모델 내부 기록과 고정된 프로젝트 사본은 공개 작업 응답에서 제외된다. 이것은 노출 가능 경로 수정이며 실제 외부 유출을 관측했다는 뜻이 아니다.

추가 검사는 병렬 모델 모의 호출, 프로젝트 분리, 실제 결과 파일 해시, 같은 요청 중복 방지, 서버 재시작, 암호화 백업 복원, 일일 한도와 중지, 호출 종료 대기, 프로젝트 변경 중 취소, 응답 캐시 비밀 제거를 다룬다. 실제 제공자 인증 후에는 한 프로젝트의 호출/결과를 먼저 확인해야 한다.

**현재 미구현:** 격리된 개발 컴퓨터에서 코드 변경·시험 실행, 성공한 후보의 승격·롤백, 매출/고객/게시 등 외부 업무 실행. 보안·상용 권리·개인정보 조건을 검토할 단계를 유지하며 무사고·법적 면책·수익을 보장하지 않는다. 실제 배포와 검사는 STATUS/LIVE_ACCEPTANCE의 최신 기록을 따른다.
