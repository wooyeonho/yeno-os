# BLACKHOLE 운영실 — 2026-09-12

기존 개인 코어의 인증·요청 원장·작업·암호화 백업에 운영 기능을 연결했다. 웹 조종석의 **운영실**에서 사용한다. 운영 배포와 실제 제공자 검증 결과는 최신 STATUS 및 별도 검증 기록을 우선한다.

## 작업 흐름

1. 여기: 장소 이름과 메모 입력 → 저장 → 수정/지도/내보내기.
2. 한끼안부: 확인할 사람과 실제 확인한 동의 기록 → 식사·기한 지정 → 응답 링크 만들기 → 직접 전달. 상대는 이름·연락처를 볼 수 없는 전용 페이지에서 한 번 답한다. 미응답은 기한이 지난 상태로 표시한다.
3. 소설: 시리즈와 설정 저장 → AI로 다음 회차 집필 → 작업과 결과에서 본문 확인 → 해당 작품의 완료 결과를 회차로 가져오기 → 편집·내보내기. 원본49개 프로젝트의 제목·설정을 자동 대체하지 않는다.
4. 영상: 제목과 장면 문구·초 입력 → MP4 제작 → 완료 결과 재생·다운로드. 무료 로컬 렌더이며 모델 호출은 없다.
5. For-Ai: 공개 URL 또는 직접 제공한 본문 선택 → 분석 → 출처·관찰값·미확인 항목이 분리된 보고서와JSON 내려받기. 제공한 소개로 생성한 검색용 파일은 수정 후보이다.

## API·비용

사용자가 기존 하루 AI 호출 상한4회를20회로 늘리는 것을 승인했다. 자동 검토는off를 유지한다. 호출 횟수는 정확한 금액 상한이 아니며 응답 미확인 요청도 횟수에 포함한다. 실제 연결된 Gemini를 우선 사용한다. 세계 현황·여기·한끼안부·For-Ai 구조 분석·무음 영상 렌더에 추가 유료 모델 키는 필요하지 않다.

별도 연결이 필요한 경우: Grok Bot은 제품 계정과 앱 인증, 생성형 영상/음성은 해당 제공자 API와 사용 예산, 자동 게시·발송은 대상 채널 계정과 해당 기능의 권한이다. 아직 연결하지 않은 서비스를 구매하거나 실행한 것으로 표시하지 않는다. 키를 GitHub·로그·URL에 저장하지 않는다.

## 저장·복구

기존 볼륨의 단일 작성자 상태를 유지하고 studio를 추가로 초기화한다. 새영상·JSON·회차·응답도 암호화 전체 백업에 포함한다. 기존 결과와 원본 포트폴리오는 보존한다. 완료 MP4는 전체 디코드와SHA-256 확인 후 등록하며 파일 디렉터리까지 동기화한다. 중단 뒤 늦은 결과는 등록하지 않고 임시 파일을 제거한다.

전체 백업 한도는16MiB이다. 신규 제작 접수 전에 실제 메타데이터·base64 결과 크기·대기/실행/일시정지 영상의최대2MiB 및For-Ai128KiB 예약·1MiB 여유를 계산해 한도 초과 접수를 막는다. 디스크 여유 공간의 실측값은 아니다. 저장 한도를 늘리거나 영상을 외부로 옮기는 장기 운영 작업은 별도 구현이 필요하다.

한끼 링크는 서버 키로 서명하고 상태·요청 캐시에 원문 토큰을 저장하지 않는다. 토큰은URL fragment로 전달되며 브라우저가같은코어의Checkin 인증 헤더로만 사용한다. 폐기·동의 철회·기한 경과 시 새 응답은 차단된다. 전체 멈춤 중 조회·폐기는 가능하다. 복원 후 소유자 키가 바뀌면 이전 링크는 무효가 된다.

## 검증의 구분

최종 로컬285/285 검사 통과(28.531초,실패·취소·생략0): 실제FFmpeg·한글 MP4·로컬HTTP·해시·중복 요청·SIGKILL·서버 재시작·암호화 백업과 별도 경로 복원. 로컬 모델 응답은 합성값이며 실제 Gemini 성공으로 계산하지 않는다. 운영 검증 스크립트는 별도 고정 요청 ID를 쓰며 유료 호출은 최대1회, 실패/미확인 유료작업을 자동 재실행하지 않는다. 폰 실기기 조작·외부 게시·실제 수신자 발송은 별도 검증이다.

한끼 기록은 일반 입력 전에 취소·폐기·동의 철회용 슬롯과 바이트를 남긴다. 일반 한도 도달 후에도 기존 링크를 닫을 수 있게 하며, 기존 요청 이력을 삭제해 공간을 확보하지 않는다.
