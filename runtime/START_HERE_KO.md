# YENO OS 0.1.1 실행 안내

이 패키지는 **실제 실행 코어가 들어 있는 첫 개발 버전**입니다. 전체 자비스의 완성판은 아닙니다. 기본 기능은 외부 AI 계정 없이 동작합니다.

## PC에서 처음 켜기

1. ZIP을 기존 `C:\JARVIS_INSTALL`과 겹치지 않는 새 폴더에 전부 풉니다. 예: `C:\YENO_REBUILD_001`.
2. `START_YENO_WINDOWS.cmd`를 더블클릭합니다.
3. 열린 실행창의 `PAIRING TOKEN` 뒤에 있는 연결 키를 브라우저의 ‘연결 키’에 붙여넣습니다.
4. 브라우저가 안 열리면 실행창의 PC 주소를 엽니다. 기본 주소는 `http://127.0.0.1:8790`입니다.
5. ‘본체 진단’을 눌러 작업이 완료되는지 확인하고 ‘결과 열기’로 실제 진단 문서를 봅니다.

Node.js 20 이상이 필요합니다. 기존 Node가 있으면 별도 패키지 설치 없이 실행됩니다. 없다면 [Node.js 공식 다운로드](https://nodejs.org/en/download)에서 지원되는 LTS를 설치한 뒤 다시 엽니다. 이 패키지는 소프트웨어를 자동 설치하지 않습니다.

현재 검증 환경은 Linux / Node.js 24.19.0입니다. Windows 실행과 실제 휴대폰 연결은 사용자의 장비에서 아직 검증하지 못했습니다. 서명된 단일 EXE나 Windows 설치 마법사는 포함하지 않았습니다.

## 지금 할 수 있는 일

| 조작 | 실제 처리 |
|---|---|
| `기억해: 내용` | 본체의 영구 저장 파일에 기록 |
| `찾아줘: 단어` | 저장된 기억에서 일치하는 내용 검색 |
| `문서 만들어: 내용` | 입력을 문단으로 나누고 출처·해시를 붙여 Markdown 파일 생성 |
| 본체 진단 | 실행 중인 환경의 메모리·프로세스·작업 상태 실측 문서 생성 |
| 개선점 찾기 | 실제 실패·중단 기록에서 개선 후보 문서 생성 |
| 멈춤·이어하기·종료 | 같은 작업을 중단·재개·종료 |
| 모든 작업 멈춤 | 진행·대기 작업을 멈추고 새 작업 시작 차단 |
| 능력·설정 | 모듈 켜기·끄기, 동시 작업 1~3개 조절 |
| 현재 상태 저장·복원 | 기억·모듈 설정·실행 규모를 보관·복원 |
| 작게·펼치기 | 간단한 명령 화면과 전체 작업 화면 전환 |

‘문서 만들기’는 제공한 텍스트를 구조화하는 기본 기능입니다. 외부 조사·추론·내용의 사실 검증을 했다고 표시하지 않습니다. 선택적 AI 작성은 초안 요청입니다. 일반적인 자유 명령에서 실제 도구를 선택·실행하는 기능은 후속 구현입니다.

기본 작업은 작아서 빠르게 끝날 수 있습니다. 이미 완료된 작업의 중단은 불가능합니다. 실행창을 닫으면 본체가 꺼지고, 다시 켠 뒤 미완료 작업은 멈춤 상태에서 확인할 수 있습니다. 자동 시작·예약 작업은 등록하지 않습니다.

## 폰에서 조종하기

`PHONE_SETUP.md`를 따라 본인 PC와 폰의 개인 연결을 구성하고 `START_PHONE_WINDOWS.cmd`로 시작합니다. 모바일 화면 코드는 포함됐으며 휴대폰 앱 설치 파일(APK)은 아닙니다. 외부 공개 배포는 하지 않았습니다.

## AI 작성 연결 — 선택

본체를 종료한 뒤 `config.example.json`을 `config.local.json`으로 복사하고 실제로 사용할 공급자의 baseUrl·model·apiKey를 **PC 로컬 파일에만** 입력합니다. 세 값이 있어야 ‘AI 설정됨’으로 표시됩니다. 연결 가능 여부가 검증됐다는 뜻은 아닙니다.

다시 실행해 ‘능력·설정’에서 AI 작성을 켜고 명령 종류를 ‘AI 작성’으로 선택하면 외부 호출을 수행합니다. 호출은 Chat Completions 호환 규격이며 모든 공급자·모델과의 호환을 보장하지 않습니다. 원격 API는 HTTPS만 허용합니다. 로컬 모델 API는 loopback HTTP도 허용합니다.

각 요청의 최대 출력은 1,800토큰, 대기 제한은 60초입니다. 월 비용 원장이나 실제 청구액 상한은 아직 구현하지 않았습니다. 공급자 계정에서 지출 한도를 먼저 설정하고 소량으로 확인해야 합니다. 기본 기능에는 AI 호출이 없습니다. 이 패키지 제작 중 실제 유료 API를 호출하지 않았습니다.

키를 채팅에 붙이거나 공유 ZIP에 넣지 마세요. 중단으로 네트워크 요청은 끊을 수 있으나 공급자가 이미 처리한 사용량까지 취소되는 것은 아닙니다. 재개하면 중단된 AI 단계의 호출이 새로 발생할 수 있습니다.

## 데이터와 복구

실행 후 생성되는 `data`에는 기억·설정·작업·결과 파일·연결 키가 있습니다. 기존 Obsidian Vault는 자동 탐색하거나 수정하지 않습니다.

화면의 복원은 **기억·모듈 설정·실행 규모**가 대상입니다. 실행 이력과 결과 파일은 보존합니다. 이전 코드 버전이나 Windows 전체를 복원하는 기능은 이번 버전에 포함하지 않았습니다. 복원 전 상태도 자동 저장하므로 그 저장 지점을 선택해 다시 돌아갈 수 있습니다.

복원 전에는 모든 진행·대기 작업을 멈춰야 합니다. 실행이 멈춘 채로 ‘그대로 두기’를 선택해 복구를 보류할 수 있습니다. 디스크 저장 파일이 손상되었을 경우 검증된 직전 백업이 있으면 시작 시 복구하고 실행 기록에 남깁니다. 두 파일 모두 손상되면 빈 상태로 덮어쓰지 않고 시작 실패로 알립니다.

수동 백업은 YENO를 종료한 뒤 `data` 폴더 전체를 다른 위치에 복사합니다. 연결 키가 들어 있으므로 개인 보관하세요. 원본 폴더를 지우거나 실행 DB를 Obsidian Sync에 직접 넣지 마세요.

## 실행 확인

Windows는 `VERIFY_WINDOWS.cmd`, 터미널은 `npm test`로 통합 검증을 실행합니다. 테스트는 별도 임시 폴더와 가짜 AI 서버를 사용하며 실제 작업 데이터나 유료 AI 계정을 사용하지 않습니다.

`VERIFICATION.md`에는 이번에 확인한 항목과 확인하지 못한 항목이 있습니다. 다음 개발 우선순위는 실제 PC·폰 왕복 확인, 유효한 AI 연결, 작업별 도구 실행, 코드 변경 후보의 별도 검증입니다.

## 0.1.1 제어와 재시도

전체 정지 해제는 잠금만 풀며 멈춘 작업은 원하는 것만 개별 재개합니다. 명령창과 빠른 작업은 응답을 확인하지 못하면 같은 탭에 요청 ID와 본문을 보관하고 같은 요청으로 재시도합니다. 별도 기억·스냅샷 폼에는 이 보완이 아직 적용되지 않았습니다. 서버는 최근 요청 ID 2,000개를 보관하므로 무기한 중복 방지나 모든 외부 행동의 정확히 한 번 실행을 보장하지 않습니다.
