# YENO OS 0.1.1 검증 기록

검증 환경: Linux x64, Node.js v24.19.0. 실행 코어·실제 HTTP·디스크·별도 프로세스를 사용했습니다. 개인 PC에 설치한 결과는 아닙니다.

## 통합 검증

명령: `npm test`

결과: **19개 통과 / 0개 실패 / 0개 생략**, 이번 전체 실행 11.835초. 2026-09-07 제작 기록 기준. 기존 코어 통합 13개와 요청 수명 검사 6개를 함께 실행했습니다.

확인한 실제 동작:

- 연결 키가 없는 API 접근 및 허용되지 않은 Host·Origin 차단.
- 지원하지 않는 명령·작업 종류의 명시적 실패, 임의 파일 경로 접근 차단.
- 같은 요청의 중복 처리 방지와 다른 내용으로 같은 요청 ID를 재사용하는 경우 거부.
- 한국어 기억 저장·검색과 프로세스 재시작 후 유지.
- 실제 Markdown 결과 파일 생성·다운로드·SHA-256 검증, 파일 손상 시 다운로드 차단.
- 작업 중단·재개·취소 및 전체 멈춤. 정지 잠금만 해제한 뒤 900ms 동안 모든 작업 상태·버전·결과가 그대로임을 확인하고, 한 작업만 명시적으로 재개했을 때 나머지가 유지됨을 확인.
- 동시 작업 한도와 모듈 비활성화 적용.
- 강제 프로세스 종료(SIGKILL) 뒤 미완료 작업을 멈춤 상태로 복원.
- 한 데이터 폴더의 중복 실행 방지.
- 오래된 화면에서 보낸 재개 명령 거부.
- 기억·설정 복원 후 작업·결과·실행 이력 보존, 복원 직전 상태 자동 보관.
- 로컬 가짜 AI 서버에 실제 HTTP 요청, 대기 중 중단에 따른 요청 취소, 늦은 응답의 결과 반영 차단, 재개 후 새로운 결과의 파일 검증.

추가 요청 수명 검사: 전송 전 저장, 서버 접수 직후 응답 유실을 가짜 전송으로 재현, 같은 탭 재로드 후 같은 ID 재시도와 단일 실행, 5xx·408·시간 초과 보존, 확정 거절 정리, 겹친 전송 합치기, 저장소 오류 시 새 명령 차단. 이 검사는 helper 동작이며 실제 브라우저 화면·DOM 조작 검사는 아닙니다.

0.1.0에서 수행한 실행기 확인: `launch.mjs --no-open`으로 실제 본체 시작, 연결 키 출력, 인증 상태 조회, HTML·JS·CSS 제공 성공. server.mjs·launch.mjs·app.js 구문 검사 통과.

## 확인하지 못한 항목

- Windows `.cmd` 실제 더블클릭 및 Windows 브라우저 자동 열기.
- 실제 Android/iOS 기기와 PC 사이 Tailscale HTTPS 왕복.
- 화면 렌더링·반응형 배치·접근성의 실제 브라우저 검사. 이 환경의 연결된 브라우저는 로컬 주소를 `ERR_BLOCKED_BY_CLIENT`로 차단하여 검사를 완료하지 못했습니다.
- 실제 외부 AI 공급자 인증·모델별 호환·청구액. 가짜 공급자 검증은 외부 공급자 성공의 증거가 아닙니다.
- 약 8GB Windows 노트북에서 장기 실행·72시간 관찰.
- 모든 정전·디스크 장애·악성 접근 상황. 현재 통합 집합의 통과는 무결점의 증거가 아닙니다.

## 이번 기능의 경계

이 버전의 ‘복구’는 기억과 설정이며 코드·Windows 전체 복구가 아닙니다. ‘개선점 찾기’는 실제 이력에 기반한 후보 문서 작성이며 자동 코드 개선이 아닙니다. ‘문서 만들기’는 입력 내용의 구조화이며 AI 추론·외부 조사 수행이 아닙니다. 범용 컴퓨터 조작과 새로운 도구 자동 장착은 후속 구현 항목입니다.

패키지에는 실제 데이터·연결 키·사용자 API 키를 포함하지 않았습니다. 테스트 파일의 키는 임시 로컬 검사 전용 고정 문자열입니다.

## 0.1.1 확인 범위 추가

명령창·빠른 작업에만 응답 유실 수명 관리를 적용했습니다. 별도 기억·스냅샷 폼은 후속 작업입니다. 서버의 중복 방지는 최근 요청 ID 2,000개 범위입니다. 모든 정전 시 파일 생성과 상태 저장의 정확히 한 번 처리를 보장하지 않습니다.

0.1.1 전체 실행 뒤 server.mjs·launch.mjs·app.js·command-request.mjs 구문 검사도 통과했습니다.

0.1.1 실행기 추가 확인: 임시 실행 사본에서 npm start -- --no-open으로 config.local.json의 지정 포트를 읽는지 확인했습니다. 인증 상태·버전 0.1.1·HTML·CSS·JS·새 command-request.mjs의 JavaScript MIME 응답이 정상입니다. Windows 셸 와일드카드 의존을 피하려고 검사 스크립트에는 동일한 두 검사 파일을 명시했습니다.
