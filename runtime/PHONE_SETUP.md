# YENO 휴대폰 연결

PC에서 실행되는 YENO를 폰의 브라우저로 조종합니다. PC가 켜져 있고 인터넷에 연결돼 있어야 합니다. 휴대폰 화면 코드는 제공하지만 이번 제작 환경에서 실제 Windows·폰 네트워크 왕복은 확인하지 못했습니다.

## 첫 연결

1. PC와 폰에 [Tailscale 공식 앱](https://tailscale.com/download)을 설치하고 본인 계정으로 로그인합니다. 이 설치·로그인은 사용자의 기기에서 한 번 필요합니다.
2. 두 기기를 Tailscale에 연결합니다. PC의 기존 YENO 실행창은 먼저 닫습니다.
3. `START_PHONE_WINDOWS.cmd`를 실행합니다. PC에서 자신의 Tailscale 주소를 읽고 개인 HTTPS 연결을 시작합니다.
4. 처음에 HTTPS 활성화를 요청하면 안내되는 Tailscale 화면에서 내용을 확인해 설정합니다.
5. 실행창의 `PHONE:` 주소를 폰 브라우저로 열고 같은 실행창의 연결 키를 입력합니다.
6. 폰에서 ‘본체 진단’을 누른 뒤 결과가 만들어지는지 확인합니다. 정상 연결 후 브라우저 메뉴의 홈 화면 추가를 사용할 수 있습니다.

연결 키는 주소에 넣지 않습니다. 현재 탭에 보관하며 ‘연결 해제’를 누르면 지웁니다. 현재 버전은 기기별 서로 다른 키를 발급하는 방식은 아니며 같은 본체의 키를 공유합니다.

## 실제 연결 방식

실행기는 로컬 본체를 `127.0.0.1:8790`에만 열고 `tailscale serve --https=9443 http://127.0.0.1:8790`으로 개인 네트워크에 연결합니다. 사용자가 정한 로컬 포트가 있으면 해당 포트를 사용합니다. 기존 9443 설정이 발견되면 덮어쓰지 않고 중단합니다. 회사·공용 기기 공유가 설정된 네트워크보다 본인 기기만 연결한 개인 환경을 사용하세요.

Serve는 Tailscale 네트워크 내부 연결 기능이며 HTTPS 및 접근 규칙을 사용합니다. 공개 인터넷에 노출하는 Funnel은 실행하지 않습니다. [Tailscale Serve 공식 설명](https://tailscale.com/docs/features/tailscale-serve)

백그라운드 상시 옵션을 사용하지 않습니다. 실행창을 유지해야 하며 재부팅 후 사용자가 다시 실행합니다. 포트 지정과 종료 방법은 [Serve CLI 공식 문서](https://tailscale.com/docs/reference/tailscale-cli/serve)를 기준으로 작성했습니다.

## 연결 문제

- **Node를 찾을 수 없음:** `START_HERE_KO.md`의 Node 설치 항목 확인.
- **Tailscale을 찾을 수 없음:** 공식 앱 설치 후 새 실행창에서 다시 시도.
- **로그인·DNS 오류:** Tailscale이 연결 상태인지, 기기 DNS가 제공되는지 확인.
- **9443이 이미 사용 중:** 이 실행기는 기존 설정을 변경하지 않습니다. Tailscale의 현재 Serve 구성을 확인하고 사용 중인 앱을 보존한 채 구성 담당자와 포트를 조정해야 합니다.
- **본체가 이미 실행 중:** 먼저 열었던 YENO 실행창을 닫고 한 개만 실행합니다.
- **폰에 연결 확인 필요 표시:** PC 전원·인터넷·YENO 실행·Tailscale 연결을 차례로 확인합니다. 오래된 화면을 현재 작동 상태로 보지 마세요.
- **정지 명령 응답을 못 받음:** PC의 작업 상태를 확인하세요. 네트워크 단절만으로 실행 중인 로컬 작업이 자동 정지하는 기능은 이번 버전에 없습니다.
- **연결 키 분실·노출:** 모든 YENO 실행창을 종료하고 `data/pairing-token` 파일을 개인 백업 위치로 이동한 뒤 다시 실행하면 새 키를 만듭니다. 단, `YENO_TOKEN` 환경변수가 지정되어 있으면 파일보다 우선하므로 해당 환경변수의 값을 교체하거나 해제해야 합니다. 적용된 키가 바뀐 뒤에는 이전 키가 거부되는지 확인하세요. 현재 기기별 키 폐기 기능은 없습니다.

폰을 잠그거나 조종 탭을 닫아도 PC가 이미 접수한 작업은 허용된 범위에서 계속 실행됩니다. PC가 꺼져 있을 때 폰에서 보낸 요청을 별도 서버가 보관하는 기능은 포함하지 않았습니다.
